# Phase D2.9 — 근거 프로토콜 연결 (is_builtin 자리 채우기)

첨부 2개가 원천이다. 문구·수치는 첨부에서만 가져온다. 임의 창작 금지.
- hourstep-evidence-archive.md (근거·수치·카피 규칙)
- hourstep-action-cards.md (동작 카드 원고 — 사용자 작성 카피 취급, 임의 수정 금지, 우려 시 지적만)

## 1. 신체정보 (마이그레이션 v5)
- settings 또는 profile 테이블: sex ('male'|'female'|null), age_group ('19-29'|'30-49'|'50-64'|'65+'|null)
- **선택 입력. 미입력(null) 시 일반값 경로.** 체중·키 등 다른 신체정보 수집 금지
- 로컬 저장만. 설정 창에 "왜 필요한가요?" 1줄: 수분 참고 기준이 성별·연령별이라서
- 입력 UI: 설정 창 새 섹션. 건너뛰기 가능 명시

## 2. 물 목표량 + 간격 제안
- src/core/waterGoal.ts 순수 함수 + vitest
- 아카이브 §2-2-1 표 사용. 액체수분 미확정 칸은 아카이브 지침대로 단순화:
  **목표 = "하루 5~6잔(200mL 기준)"** 표기 + 확정치 있는 조합(남19-29=1,200mL, 여50-64=1,000mL)은 mL 병기
- 미입력 시: "성인 기준 하루 5~6잔" 일반값
- 간격 제안 함수: suggestWaterInterval(liquidMl, sessionHours) → 분. 결과는 **제안만** — 자동 변경 금지, 설정에서 "제안 적용" 버튼
- 표기 규칙: "목표" 아니라 "참고 기준". 활동·더위 시 더 필요 안내 1줄
- 질환 고지: 물 설정 화면에만 아카이브 §2-3 문구 1줄

## 3. 동작 로테이션 (스트레칭 카드)
- src/core/actionRotation.ts 순수 함수 + vitest
- 카드 원고의 8동작(A1~C2), 배치 제안의 로테이션 순서 그대로
- 발화마다 다음 동작으로 전진. 상태는 DB(마지막 인덱스). 세션 넘어가도 이어짐
- 오버레이 카드: 동작 이름 + 방법 첫 줄만 (540×139 제약). [자세히] → 메인 창 상세로
- 상세 화면: 방법 전체 + 시간 + 출처 줄 (카드 원고 그대로)
- duration은 동작별 카드 원고의 시간 참고하되, 행동의 duration_sec 설정이 우선 (충돌 시 설정값)

## 4. 눈·물 카드 문구 교체
- 눈휴식 카드 → D1 문구 (멀리 보기 + 깜빡이기)
- 물 카드 → E1 문구
- 기존 BEHAVIOR_MESSAGE의 임시 행동 지시 문구를 원고로 대체
- is_builtin=true 행동에만 적용. 사용자 생성·AI 행동은 기존 그대로

## 5. 근거 보기 화면
- 설정 or 상세에 "왜 이 주기인가요?" 진입점
- 내용: 아카이브 §1-4, §2-4, §3-3의 카피 예시 + 간격 관련 안내
  (스트레칭: "연구는 20~30분대 집중" / 눈: "원칙은 20분마다" 병기 — 아카이브 §4 표)
- 공통 고지 1줄 고정 (카드 원고 상단 고지문)

## 검증
- vitest: waterGoal (성별×연령 6조합 + null), suggestWaterInterval 경계, actionRotation (전진·순환·DB 왕복)
- v4→v5 마이그레이션 기존 데이터 보존
- --debug-cmd: 스트레칭 2회 연속 발화 → 동작이 로테이션 순서대로 다른지 dump
- 문구 검증: 컴파일된 문자열에 "개선됩니다/치료/예방됩니다" 류 단정 표현 0건 (grep)
- D1~D2.8 회귀 유지
