# 0011. 화면 동작 규칙은 컴포넌트 안에 두지 않고 순수 함수로 뺀다

- 날짜: 2026-08-09
- Phase: D2.8 후속
- 상태: 채택
- 관련: `src/core/behaviors.ts` (`sanitizeDigits` / `liveNumber`),
  `src/components/NumberField.tsx`, `docs/decisions/0004-rust-clock-ts-judgment.md`

## Problem

같은 버그가 **두 번** 났다.

| | 언제 | 증상 | 놓친 것 |
| --- | --- | --- | --- |
| 1회 | D2.6 후속 | 행동 간격칸에서 마지막 글자를 지우면 값이 시드로 되돌아간다 | — (여기서 규칙을 만들었다) |
| 2회 | D2.8 | 세션 미시작 리마인더칸에서 같은 증상 | **clamp 함수만 통일하고 컴포넌트를 안 바꿨다** |

두 번 다 원인은 clamp 함수가 아니라 **clamp 를 언제 부르느냐**였다.
`onChange` 에서 부르면 빈칸이 그 자리에서 기본값으로 확정되고, 커서가 앞으로 밀려
더 지울 수도 없다. 지우는 중일 뿐인데 값이 바뀐다.

D2.6 후속에서 이 판단을 고쳤지만, 고친 자리가 **컴포넌트 안**이었다.

```tsx
// NumberField.tsx — 규칙이 여기 살고 있었다
const n = Number(next)
if (next !== '' && n >= min && n <= max) onChange(n)
```

그래서:

- **테스트가 닿지 않는다.** vitest 는 `src/core` 순수 모듈만 돌린다.
  컴포넌트를 테스트하려면 jsdom + testing-library 를 새로 들여야 한다
- 규칙이 **읽히지 않는다.** 다음 사람이 같은 칸을 만들 때 참조할 이름이 없다.
  실제로 D2.8 에서 clamp 상수는 찾아서 통일했는데 이 두 줄은 못 봤다
- 결과적으로 **회귀를 코드 리뷰와 수동 확인에만 맡기게 된다**

## Decision

**화면 동작을 좌우하는 판단은 `src/core` 의 순수 함수로 뺀다. 컴포넌트에는 배선만 남긴다.**

숫자 입력칸의 경우 판단이 둘이고, 둘 다 함수가 됐다.

| 함수 | 언제 | 무엇을 정하나 |
| --- | --- | --- |
| `sanitizeDigits(raw)` | 타이핑마다 | 화면에 남길 문자열 (숫자만, 선행 0 제거, **빈칸 허용**) |
| `liveNumber(digits, min, max)` | 타이핑마다 | 지금 위로 올려도 되는 값. 아니면 `null` |
| `clamp*(value)` | blur | 최종 확정값 |

```tsx
// 컴포넌트에 남은 것 — 무엇을 하라는 판단이 아니라 언제 부르라는 배선
const next = sanitizeDigits(e.target.value)
setDraft(next)
const live = liveNumber(next, min, max)
if (live !== null) onChange(live)
```

이건 「시계는 Rust, 판단은 TS」(`0004`)와 같은 갈래다. 거기서는 **어디서 계산하나**를
갈랐고, 여기서는 **판단과 배선**을 가른다. 목적도 같다 — 판단을 테스트가 닿는 곳에 두는 것.

### 어디까지가 「판단」인가

전부 빼면 컴포넌트가 없어진다. 기준은 **"틀리면 사용자가 알아채는가"** 다.

- **뺀다**: 빈칸 허용 여부, 범위 판정, 경계 복구, 정렬·병합 규칙, 무엇을 언제 보여줄지
- **안 뺀다**: `useState`/`useEffect` 배선, 이벤트 연결, 클래스 이름 조립, 포커스 ref

`NumberField` 에 남은 "포커스 중에는 외부 값을 덮지 않는다"(`focused` ref)는 뺄 수 없다 —
React 생명주기 그 자체다. 대신 그 규칙은 주석으로 크게 적어 뒀다.

### 왜 jsdom + testing-library 를 들이지 않았나

가장 곧은 답은 컴포넌트를 그대로 테스트하는 것이다. 버렸다.

- devDependency 두세 개와 별도 test environment 설정이 는다. 이 프로젝트는 의존성을
  의도적으로 얇게 유지해 왔다 (`0010` 에서 stylelint 를 버린 것과 같은 계산)
- 무엇보다 **테스트 대상이 판단이 아니라 렌더 결과가 된다.** "3에서 백스페이스를 치면
  input 의 value 가 ''" 를 확인하는 테스트는 규칙이 아니라 구현을 붙잡는다.
  `liveNumber('', 1, 480) === null` 이 규칙 자체다
- 순수 함수 쪽이 **읽는 문서로도 낫다.** 다음에 숫자칸을 만드는 사람이 함수 이름과
  테스트를 보면 규칙을 안다

컴포넌트 렌더를 정말 확인해야 할 때가 오면 그때 들인다. 지금은 필요가 없다.

## Consequences

- 회귀 케이스가 vitest 에 들어왔다. `liveNumber` 를 망가뜨리면 **4건이 실패한다**
  (일부러 `return Number(digits)` 로 바꿔 확인했다)
- 규칙에 **이름이 생겼다.** 다음 숫자칸은 `liveNumber` 를 검색하면 찾는다
- `src/core` 가 UI 성격의 함수를 갖게 됐다. 「IO 없는 순수 모듈」 규칙은 그대로 지킨다 —
  React·Tauri import 금지는 eslint 가 강제하고 있고, 이 함수들도 그 안에 있다
- 컴포넌트 코드가 짧아진 만큼 **주석의 몫이 커졌다.** 왜 빈칸을 허용하는지는 함수 쪽에,
  왜 포커스 중에 덮지 않는지는 컴포넌트 쪽에 적어 두어야 둘 다 읽힌다
