# 0010. 디자인 값은 토큰 한 곳에서만, 위반은 stylelint 가 아니라 vitest 로 막는다

- 날짜: 2026-08-09
- Phase: D2.8
- 상태: 채택
- 관련: `src/styles/tokens.css`, `src/styles/components.css`, `src/styles/tokens.test.ts`,
  `src/components/`, `docs/design-system.md`

## Problem

D2.5 에서 색을 CSS 변수로 옮겼다. 그런데 **규격 문서가 없었다.** 변수는 있는데
"어떤 이름이 있고, 무엇이 그 이름을 써야 하는가"가 어디에도 없으니, 창별 CSS 에
새 값이 계속 생겼다. D2.8 착수 시점 실측:

- 같은 성격의 버튼이 **네 벌** — `.ghost`(메인) / `.chip`(설정) / `.btn`(오버레이) /
  `.session__toggle`. 라이트 모드를 붙일 때 네 군데를 따로 손봐야 했다
- 반경 **8종** (6·7·8·9·10·12·14·18px), 글자 크기 **12종** (11~34px, `12.5px` 포함)
- 여백이 4px 격자를 벗어난 값 다수 (22·26·9·5·3·1px)
- 그리고 **대비 실패 3건** — 다크/라이트 `--text-faint`, 주 버튼 위 흰 글자.
  아무도 재 본 적이 없어서 몰랐다

문제의 본질은 값이 흩어진 것이 아니라 **흩어지는 것을 막는 장치가 없다**는 것이다.
D2.5 에서 한 번 정리했는데 세 Phase 만에 같은 상태로 돌아왔다.

## Decision

### 1. 값의 단일 출처는 `src/styles/tokens.css` 하나

색·간격·반경·그림자·타이포·모션을 두 벌(다크 기본 / 라이트)로 정의한다.
**창별 CSS 에는 색 리터럴(`#`/`rgb()`)과 임의 px 여백을 쓰지 않는다.**
새 값이 필요하면 토큰부터 정의하고 그 이름을 참조한다.

`base.css` 가 `tokens.css` 와 `components.css` 를 `@import` 하므로, 창별 엔트리
(`main.tsx` × 3)는 예전처럼 `base.css` 하나만 읽는다 — 배선을 늘리지 않았다.

### 2. 규칙을 문서 + **테스트**로 이중화한다

규격은 `docs/design-system.md` 한 장에 두되, **지키는 일은 사람에게 맡기지 않는다.**
`src/styles/tokens.test.ts` 가 다음을 강제한다.

- 토큰 밖 CSS 5개 파일에 색 리터럴 **0건**
- 그 파일들의 `padding`/`margin`/`gap` 이 전부 `var(--sp-*)` · `0` · `%` · `calc(토큰)`
- `overlay.css` 에 `--shadow-*` 없음 (창이 카드 실크기라 그림자가 잘린다 — 0005)
- 라이트/다크 **두 벌의 토큰 이름 집합이 같다**
- 검사 대상 파일 목록이 기대와 일치한다

### 3. 컴포넌트는 `src/components/` 에서만 만든다

`Button` / `NumberField` / `Checkbox` / `Card` / `Section` / `EmptyState`.
창별 CSS 에 새 버튼 스타일을 만들지 않는다.

### 왜 stylelint 가 아닌가

가장 뻔한 답은 stylelint 였다. 버렸다.

- 규칙이 **네 개**다. 그것 때문에 devDependency 와 설정 파일(+ eslint 와의 실행 경로 이원화)이
  늘어난다. 이 프로젝트는 의존성을 의도적으로 얇게 유지해 왔다
- 규칙 중 절반(**두 테마의 토큰 이름 집합 일치**, **오버레이 그림자 금지**)은 범용 린터의
  기성 규칙으로 표현되지 않는다. 어차피 커스텀 플러그인을 써야 한다
- vitest 는 **이미 돌고 있다**. CSS 를 문자열로 읽고 정규식 몇 줄이면 끝난다.
  검증이 `pnpm test` 한 곳에 모이는 편이 낫다

### 왜 토큰을 읽을 때 `node:fs` 가 아니라 `import.meta.glob(?raw)` 인가

`node:fs` 는 `@types/node` 를 새로 요구했다(의존성 추가). 그보다 중요한 이유는
**glob 이 새 CSS 파일을 자동으로 검사 대상에 넣는다**는 것이다. 파일을 하나씩 import 하면
나중에 만든 창은 조용히 규칙 밖으로 빠진다.

대신 vitest 기본값 `css: false` 가 CSS 를 **빈 모듈로 갈아치워** 모든 규칙이 빈 문자열을
검사하고 통과해 버렸다. `vite.config.ts` 에 `test.css = true` 를 주고, **파일 내용이 비면
실패하는 테스트**를 따로 두어 같은 사고가 되풀이되지 않게 못 박았다.

### 왜 주 버튼의 그러데이션을 없앴나

`--accent-hover` 라는 토큰과 그러데이션은 같이 갈 수 없다("hover 때 어느 정지점을 바꾸나").
게다가 두 정지점 중 밝은 쪽(#5b93ff)은 흰 글자와 **2.9:1** 로 큰 글자 기준(3:1)조차 못 넘겼다.
단색 `--accent`(#2f6fe0)로 바꿔 흰 글자 **4.70:1** 을 확보했다. 라이트/다크가 같은 값인 이유는
흰 글자가 4.5:1 을 넘는 파랑의 폭이 좁기 때문이고, 어두운 배경 위에 **글자로** 쓰는
강조색은 `--accent-text` 가 따로 맡는다.

### 왜 Toggle 을 만들지 않았나

원래 계획에는 `Toggle / Checkbox` 가 같이 있었다. 이 앱의 on/off 는 **전부 체크박스**이고
스위치를 쓰는 자리가 하나도 없다. 쓰이지 않는 컴포넌트는 그냥 죽은 코드다.
필요해지는 날 만든다.

### 왜 타이포 4단에 예외를 두 개 남겼나

`--fs-display`(30px, 경과시간·카운트다운)와 `--fs-icon`(24px, 카드 이모지)은 스케일 밖이다.
카운트다운 숫자는 **눈을 감고 있다가 뜨거나 스트레칭 자세에서 곁눈질로 읽는** 값이라
본문 스케일(최대 20px)로 줄이면 기능이 깎인다. 이모지 글리프는 애초에 글자가 아니다.
예외를 없애는 대신 **쓰는 자리를 문서에 전부 나열**해서 번지지 않게 했다.

## Consequences

- 새 화면·새 색을 추가하려면 `tokens.css` 를 먼저 고쳐야 한다. 한 단계 느려지지만,
  그 한 단계가 D2.5 → D2.8 사이에 벌어진 일을 막는다
- **대비 3건이 실제로 고쳐졌다** (AA 4.5:1): 다크 `--text-subtle` 3.68→5.08,
  라이트 3.10→4.85, 흰 글자 on 주 버튼 2.9→4.70
- 주 버튼 모양이 바뀐다(그러데이션 → 단색). 지각 판단은 사용자 몫으로 남긴다
- 오버레이 카드 클래스가 `.card*` → `.overlay-card*` 로 바뀌었다.
  공통 `Card` 컴포넌트와 이름이 겹쳐서다 — **오버레이 카드는 `Card` 를 쓰지 않는다**
  (그림자·바깥 여백 금지 규칙이 다르다, 0005)
- 테스트가 CSS 를 문자열로 읽으므로 `vite.config.ts` 의 `test.css` 를 끄면 조용히
  무력화된다. 그래서 "내용이 비면 실패" 검사를 같은 파일에 넣어 뒀다
