# 0004. 시계는 Rust, 판단은 TS

- 날짜: 2026-08-07
- Phase: D1
- 상태: 채택
- 관련: `src-tauri/src/session.rs`, `src/core/scheduler.ts`, `src/windows/overlay/OverlayWindow.tsx`

## Problem

CLAUDE.md 핵심 결정 4번은 **스케줄러를 IO 없는 순수 함수**로 두라고 한다. 모바일(Expo)과
공유할 전제라 `now` 를 인자로 주입받고 플랫폼 API 를 참조하지 않는다.

그런데 순수 함수는 스스로 돌지 않는다. D1 에서 실제로 정해야 했던 건
**"그 함수를 무엇이 주기적으로 호출하느냐"** 였다.

이 앱의 알림 주기는 30~60분이다. 그리고 오버레이 웹뷰는 **평소 숨겨져 있다.**

## Options

### A. 웹뷰의 JS 타이머 (`setTimeout` / `setInterval`)

가장 자연스러워 보이지만 **안 된다.** Chromium 은 숨겨진 창의 타이머를 분 단위로
스로틀링한다. 50분 뒤에 깨워달라고 걸어두면 언제 깨는지 보장이 없다.
웹뷰를 계속 띄워두는 건 애초에 오버레이 설계와 모순이다.

### B. Rust 가 다음 due 시각을 직접 계산해서 그때 깨우기

정확하지만 **스케줄 로직이 Rust 로 넘어간다.** 순수 함수 규칙이 무너지고, 모바일과
공유할 수 없게 되며, 테스트도 vitest 에서 Rust 테스트로 옮겨야 한다. 규칙 4를 버리는 셈.

### C. Rust 는 1초 tick 만, 판단은 TS

Rust `std::thread::sleep` 은 스로틀링 대상이 아니다. 1초마다
`app://tick { now }` 를 오버레이 웹뷰로 보내고, **무엇이 언제 뜨는지는 TS 가**
`computeNextOccurrences()` 로 계산한다.

## Decision

**C 를 택한다. Rust = 시계, TS = 판단.**

- Rust 는 "지금 몇 시인지"만 안다. 행동·간격·스누즈 규칙을 전혀 모른다
- TS 는 tick 을 받아 세션 시작부터 지금까지의 예정분을 뽑고, 아직 안 띄운 것 중 첫 번째를 띄운다
- 세션 상태(`startedAt`)의 단일 출처는 Rust(`session.rs`) — 트레이 메뉴가 거기 있으니까

1초 tick 의 비용은 무시할 만하다. 스레드 하나가 자고 일어나 이벤트를 하나 보낼 뿐이다.

## Consequences

### 이득: 가상 시각이 공짜로 생겼다

Rust 의 `now_ms()` 에 오프셋 하나(`CLOCK_OFFSET_MS`)만 더하면
`--debug-cmd tick:1800000` 이 "30분 뒤"가 된다. **스케줄러의 `now` 주입과 완전히 같은 경로**라
검증용 샛길이 아니다. 50분 간격 알림을 50분 기다리지 않고 검증할 수 있게 된 게 이 결정의
가장 큰 부수 효과다 (릴리스 빌드에는 이 오프셋을 건드리는 경로가 없어 항상 0).

### 대가: 매 tick 전체 재계산

TS 는 매초 `computeNextOccurrences(session, behaviors, startedAt, elapsed, snoozes)` 를 부른다.
세션 시작부터 지금까지 전 구간을 다시 계산한다는 뜻이다. 10시간 세션 × 3행동이면 수십 개라
무시할 비용이지만, 세션 길이에 비례해 늘어난다. 느려지면 마지막 dueAt 을 캐시하면 된다.

### 밀린 알림 처리가 필요해졌다

절전에서 복귀하거나 가상 시각을 크게 점프시키면 여러 occurrence 가 한꺼번에 due 가 된다.
그대로 두면 카드가 몰려 뜬다. `STALE_MS`(2분)보다 밀린 것은 **소진 처리**하고,
남은 것은 현재 카드가 닫힐 때까지 큐로 밀린다.

부작용: `--debug-cmd tick:` 은 **정확히 due 시각에 착지해야** 카드가 뜬다.
30분 간격 행동을 검증하려면 `tick:1800000` 처럼 딱 맞춰야 하고, 57분 같은 어중간한 지점으로
점프하면 30분 것은 27분 밀렸다고 판단해 조용히 소진된다.

### 오버레이 웹뷰가 세션 런타임을 갖게 됐다

발화 판단·CompletionLog·리마인더가 전부 `OverlayWindow.tsx` 에 산다. 창 하나가 UI 와
런타임을 겸하는 셈이라 어색하지만, **항상 살아 있는 유일한 웹뷰**라서 다른 선택지가 없었다.
D2 에서 DB 쓰기까지 여기로 들어왔다.
