# 0008. AI 루틴은 「구글 딥링크 + 복사·붙여넣기」로 가져온다 (앱이 결과를 읽지 않는다)

- 날짜: 2026-08-08
- Phase: D2.6
- 상태: 채택
- 관련: `src/core/aiQuery.ts`, `src/core/routineParse.ts`,
  `src/windows/settings/RoutineFinder.tsx`, `src-tauri/src/db.rs` (마이그레이션 v3),
  `docs/decisions/0007-behaviors-runtime-source-db.md`

## Problem

내장 3종(🧘/💧/👀)은 "앉아서 일하는 사람"의 최대공약수다. 실제 고민은 개별적이다 —
"사무직인데 어깨가 아픔", "모니터를 오래 봐서 눈이 침침함". 이걸 행동으로 바꾸려면
사용자가 직접 이름·간격·문구를 지어내야 하는데, 그 지식이 없어서 앱을 켠 것이다.

MVP 제약은 그대로다: **계정 없음, 서버 없음, API 키 없음** (CLAUDE.md 결정 5). 그러면
"AI 가 루틴을 만들어 준다"를 어떻게 붙이나.

## Decision

**앱은 프롬프트를 만들어 보여주고, 답은 사용자가 복사해 온다. 어느 AI 로 갈지는 사용자가 고른다.**

```
고민 입력 → 앱이 프롬프트 조립(전문 표시) → [복사] 또는 [AI 열기]
→ 기본 브라우저로 구글 AI 모드 / ChatGPT / Claude → 사용자가 결과 복사
→ 앱에 붙여넣기 → 파싱 → 미리보기 → 확인 → 행동 추가
```

### 프롬프트를 URL 에 태우고 끝내지 않는다

처음엔 구글 검색 URL 에 질의를 실어 보내는 것으로 끝냈다. 두 가지가 걸렸다.

- **사용자가 무엇을 보내는지 모른다.** 자기 증상이 담긴 문장이 URL 안에 숨어 나간다.
  프롬프트 전문을 화면에 그대로 띄우고(접지 않는다) 보고 보내게 했다
- **구글에 묶인다.** `q` 파라미터로 프롬프트가 주입되는 건 구글뿐이고, ChatGPT·Claude 는
  홈만 열린다. URL 주입에 기대면 다른 AI 를 쓸 수 없다

그래서 **이동할 때 클립보드에 자동으로 넣는다.** 복사 없이 이동하면 붙여넣을 게 없어
기능 자체가 무의미하기 때문이다. 구글도 예외로 두지 않는다(URL 에 이미 실려 있어도
사용자가 다시 붙여넣을 수 있어야 한다). 프롬프트가 URL 에 안 실리는 대상은 버튼 문구에
「열기 (붙여넣기 필요)」라고 밝혀 기대를 어긋나게 하지 않는다.

클립보드는 `navigator.clipboard` 가 아니라 `tauri-plugin-clipboard-manager` 를 쓴다.
웹뷰의 클립보드 API 는 보안 컨텍스트·포커스 조건에 걸려 패키징 후 조용히 실패할 수 있다.
그래도 실패하면 안내만 남긴다 — 프롬프트 전문이 화면에 있으니 직접 선택해 복사할 수 있다.

주소는 `AI_TARGETS` / `TARGET_URL` **한 곳에만** 적는다. 서비스 도메인은 바뀐다
(chat.openai.com → chatgpt.com 처럼). UI 도 테스트도 이 상수를 참조한다.

### 왜 앱이 직접 읽지 않나

- **API 키·서버가 필요 없다.** Anthropic/OpenAI 를 붙이면 키 보관·과금·계정이 딸려 온다.
  그건 MVP 범위 밖이고, 지금 필요한 건 "월 1회 쓸까 말까 한 루틴 생성" 한 번이다
- **스크래핑을 하지 않는다.** 앱 내 웹뷰로 구글을 띄우거나 HTTP 로 결과를 긁으면
  약관 문제이기 이전에 "사용자 몰래 뭔가 한다"는 인상을 준다. 브라우저는 **기본 브라우저**로
  열고(`tauri-plugin-opener`), 앱은 그 창을 보지 못한다
- **문구를 우리가 지어내지 않는다.** CLAUDE.md 규칙 6(효용 단정 금지)을 지키는 가장 확실한
  방법은 앱이 문장을 생성하지 않는 것이다. 저장되는 문구는 전부 사용자가 보고 확인한 텍스트다

대가: 복사·붙여넣기 두 번이 사용자 몫이다. 자동화된 경험보다 확실히 번거롭다. 그래도
"루틴을 처음 만들 때 한 번" 쓰는 기능이라 이 마찰을 감수할 만하다고 봤다.

### 구조화 방법: 표식 블록 + 관대한 파서

질의 끝에 출력 형식을 지시한다.

```
[HOURSTEP]
이모지|행동이름|간격(분)|알림문구
[/HOURSTEP]
```

JSON 을 요구하지 않았다. AI 는 JSON 을 코드펜스로 감싸고 주석을 달고 후행 쉼표를 남긴다 —
`JSON.parse` 는 그 중 하나만 어긋나도 전부 실패한다. 파이프 구분 줄은 **줄 단위로 실패**해서
나머지를 살릴 수 있다. 실제로 파서는 코드펜스·마크다운 볼드·표 형식·전각 파이프(｜)·
`"30분"` 같은 단위 혼입을 전부 흡수하고, 못 읽은 줄만 세어 알려준다.

블록이 여러 개면 **항목이 나오는 마지막 블록**을 쓴다. AI 는 형식을 설명하며 빈 템플릿을
먼저 따라 쓰는 일이 잦고, 질의가 "답변 마지막에 정리해줘"라고 요구하기 때문이다.

### 실패는 에러가 아니라 폴백

파싱 실패로 끝내지 않는다. 붙여넣은 원문을 그대로 둔 채 빈 입력 줄을 하나 띄워
보고 직접 채우게 한다. 성공이든 실패든 이후 경로(미리보기 → 확인 → 삽입)는 완전히 같다.

### 직삽입 금지

파싱 결과는 아직 행동이 아니다(`RoutineItem`). 사용자가 미리보기에서 항목별로 체크하고
수정한 뒤 [추가]를 눌러야 `behaviors` 에 들어간다. 저장은 손으로 추가할 때와 **같은 함수**
(`saveBehaviorsAndBroadcast`)를 타므로 실행 중 세션에 즉시 반영된다.

### `source` 컬럼을 새로 만든다 (`is_builtin` 겸용 금지)

D2.6 스펙은 "D2.5 컬럼 재사용"이라고 적혀 있었지만 그런 열은 없었다. `is_builtin` 은
"내장 3종이냐"는 다른 사실이고 근거 기반 프로토콜을 붙일 자리다(0007). 한 열에 두 의미를
태우면 둘 중 하나는 반드시 어긋난다 — 마이그레이션 v3 로 `source TEXT NOT NULL DEFAULT 'user'`
를 추가했다. 값은 `'user' | 'ai'` 두 가지뿐이고, `'builtin'` 을 넣지 않는 이유도 같다.

## Consequences

- 네트워크 코드가 앱에 **없다**. 늘어난 외부 접점은 `openUrl()` 과 클립보드 쓰기뿐이다
  (`opener:default` 가 이미 https 를 허용하므로 추가한 권한은 `clipboard-manager:allow-write-text`
  하나. 읽기 권한은 주지 않았다 — 붙여넣기는 사용자가 직접 한다)
- 자동 검증은 **문자열 조립까지만** 한다. 실제 브라우저가 열리는지는 눈으로 본다.
  붙여넣기 이후는 `--debug-cmd ai-import` 로 고정 샘플 답변을 태워 전 구간을 검증한다
- 파서는 신뢰 경계다. 어떤 입력에도 예외를 던지지 않고, 항목 단위로 범위를 검사한 뒤
  저장 직전 `normalizeBehavior` 를 한 번 더 통과한다
- AI 유래 문구도 카드에 그대로 뜬다. 미리보기에 고정 고지 한 줄
  ("참고용이며 전문의 상담을 대체하지 않습니다")을 두고, 설정 목록에 `AI` 태그를 붙여
  출처를 남긴다
