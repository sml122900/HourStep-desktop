# 0015. 단계 타이머는 설정값보다 근거 유지시간을 우선하고(floor), 전환음은 새로 만들지 않는다

- 날짜: 2026-08-14
- Phase: D2.11
- 상태: 채택
- 관련: `src/core/actionSteps.ts`, `src/constants/strings.ts`(`ACTION_CARDS[*].steps`),
  `src/windows/overlay/OverlayWindow.tsx`, `src/windows/sound.ts`,
  `docs/content/hourstep-action-cards.md`, `docs/decisions/0012`(근거 프로토콜),
  `docs/decisions/0014`(카운트다운 창 리사이즈 재사용 — 같은 "새 메커니즘 안 만들기" 결)

## Problem

카운트다운 중 동작 방법을 단계별로 자동 전환하며 보여주려면 두 가지가 걸린다.

① 원고 8종(A1~C2)의 단계 duration 은 v4 기본 행위 시간(60초) 기준으로 저작됐는데,
`Behavior.durationSec` 은 설정에서 사용자가 자유롭게 바꿀 수 있는 값이다(20초든
120초든). 단계 duration 합이 그 실제 값과 항상 정확히 일치해야 UI 가 자연스럽다.

② 원문에 "15~30초 유지"·"각 15초"처럼 **시간이 명시된** 단계는 그 시간 자체가
인용한 연구의 근거(`docs/decisions/0012`)다. 사용자가 행위 시간을 아주 짧게
설정하면(예: 스트레칭 20초) 비례 배분만으로는 B1 좌우가 각 10초가 돼 원문
하한(15초)보다 짧아진다 — 근거를 배신하는 값을 보여주게 된다.

③ 단계가 자동 전환될 때 소리로도 알려주면 좋겠는데, CLAUDE.md 규칙(6) 은 임의
문구·연출 추가에 보수적이고, 알림음은 이미 두 지점(`start`/`end`)으로 정리돼
있다(`docs/decisions/0009` 언저리 관례). 세 번째 소리를 새로 합성할지, 기존 걸
재사용할지 정해야 했다.

## Decision

### 목표 시간에 맞춰 재배분하되, `minDurationSec` 아래로는 절대 안 내려간다

`scaleSteps(steps, targetDurationSec)`:

1. 원문에 시간이 명시된 단계에만 `minDurationSec` 을 원고에 적어 둔다(범위면
   하한, 고정값이면 그 값). 회수만 적힌 동작(B2·B3·C2)과 이미 원문·실제 카운트다운이
   어긋나 있던 A2(그대로 두기로 확인받음)에는 두지 않는다
2. water-filling 으로 배분한다 — 비례 배분이 `minDurationSec` 아래로 내려가는
   단계는 그 floor 에 고정하고, 남은 단계끼리 다시 비례 배분을 반복한다
3. **목표 시간 자체가 floor 합보다 짧으면 floor 합을 그대로 쓴다.** 예: C1 은
   4단계 모두 이미 15초가 floor 라 합이 60초 — `duration_sec` 을 8초로 줄여도
   실제로는 60초를 돈다. **사용자가 설정한 값보다 근거 유지시간을 우선했다** —
   설정을 정확히 지키는 것보다, 인용한 연구가 측정한 시간 아래로 스트레칭
   유지시간을 보여주지 않는 쪽이 제품 신뢰도에 더 중요하다고 판단했다
4. 정수 반올림은 largest-remainder 방식 — 합이 항상 목표(또는 floor 합)와
   정확히 같고, 반올림 때문에 0초 단계가 생기지 않는다

대안으로 "설정 화면에서 스트레칭 `duration_sec` 자체를 근거 유지 범위(예:
30~90초)로 클램프"도 검토했지만 채택하지 않았다 — 그러면 행동마다 다른
범위 제약을 설정 UI 레벨에 특별 취급으로 넣어야 하고(다른 행동은 자유
범위), 판단 로직이 컴포넌트/검증 계층으로 흩어진다(`docs/decisions/0011`
「화면 동작을 좌우하는 판단은 순수 함수에」 원칙과 어긋남). floor 를 순수
함수 하나(`scaleSteps`) 안에 가두면 재사용 가능하고 테스트하기도 쉽다.

### 전환음은 새로 만들지 않고 `end` 톤을 그대로 재사용한다

`SoundCue` 에 `'step'` 을 추가했지만 정의(`freq`/`length`)는 `end` 와 **완전히
동일**하다 — 별도 cue 키를 둔 건 stdout 검증 로그(`sound step …` vs
`sound end …`)에서 "단계 전환"과 "카운트다운 완전 종료"를 구분하기 위해서일
뿐, 사용자가 듣는 소리는 새로 늘지 않는다. 손목(C1)은 15초마다 4번 울리면
과하다는 도그푸딩 피드백을 받아 `muteStepChime` 콘텐츠 플래그로 그 동작만
전환음을 생략했다(카드 열림음·카운트다운 종료음은 그대로 남는다) — 볼륨을
낮추는 "약하게" 옵션도 검토했으나, 기존 `playCue` 가 큐 단위로만 게인을
계산해 특정 큐만 다른 볼륨을 쓰려면 볼륨 파라미터화가 필요해 범위가
커진다. 완전 생략이 코드 변경을 `if (!muteStepChime) playCue(...)` 한 줄로
끝내면서도 피드백("과하다")을 해결하는 가장 작은 수정이었다.

## Consequences

- 스트레칭 `duration_sec` 을 60초보다 짧게(예: 30초) 설정한 사용자는, C1 이
  로테이션에 걸리는 날만 실제 카운트다운이 60초(floor 합)로 늘어나는 걸
  본다 — 다른 7개 동작은 대부분 floor 가 없거나 낮아 설정값 그대로 돈다.
  UI 상 이 차이를 명시적으로 알리지는 않는다(카드 자체가 남은 시간을 보여주므로
  "생각보다 길게 도네" 정도로 자연스럽게 드러난다고 판단) — 혼란스러우면
  다음 Phase 에서 "근거 유지시간 때문에 조금 더 길게 돕니다" 같은 안내를
  추가할 수 있다
- `steps` 는 `ACTION_CARDS`(콘텐츠, `strings.ts`) 에만 있고 DB 스키마는
  안 바뀌었다 — 마이그레이션 없음. `Behavior.durationSec` 하나만 여전히
  DB 가 들고 있고, 단계 배분은 매번 그 값으로 즉석 계산한다(캐시 없음)
- `sound step` 로그 키가 늘어 `--debug-cmd` 자동 검증에서 "전환음이 실제로
  안 울렸는가"(C1 뮤트 확인)를 `grep` 으로 바로 볼 수 있게 됐다 — D2.11
  화면 검증에서 실제로 이 방식으로 확인했다(`docs/daily/2026-08-14-phase-d2.11.md`)
