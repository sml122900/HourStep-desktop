## 1. 「AI 열기」 대상 확장 + 드롭다운

버튼 3개(구글 / ChatGPT / Claude)를 **버튼 1개 + 드롭다운**으로 바꿨다.

```
[구글 AI 모드 열기]  [ChatGPT ▾]  [ChatGPT 열기 (붙여넣기 필요)]
```

채팅형 8곳, **영문 이름 알파벳 내림차순**:
Qwen · Perplexity · Kimi · Grok · Gemini · DeepSeek · Claude · ChatGPT

### 판단 두 가지

**① 화면 배치와 URL 주입을 별개 필드로 뒀다.** 지금은 `kind === 'search'` 인 것과
`injectsPrompt` 인 것이 둘 다 구글 하나라서 한 필드로 합치고 싶어진다. 합치면 ChatGPT 처럼
`?q=` 를 받는 채팅형을 나중에 주입 대상으로 바꾸는 순간 **그놈이 드롭다운에서 튀어나와
버튼이 된다.** `is_builtin`/`source` 를 나누며 편 논지와 같다 (`docs/decisions/0008`).

**② 새로 넣은 8곳은 전부 `injectsPrompt: false` 다.** 일부는 `?q=` 를 받는 걸로 알려져
있지만 켜지 않았다 — 파라미터 이름과 지원 여부가 서비스마다 다르고 예고 없이 바뀌는데,
**틀리면 에러가 아니라 빈 채팅이 열리고 프롬프트가 조용히 사라진다.** 어느 쪽을 눌러도
클립보드 복사는 그대로 되므로 붙여넣기 한 번이면 된다. 조용한 실패보다 한 동작이 낫다.

### 곁가지

드롭다운이 옆 버튼보다 2px 높았다. 그 자리에 `28px` 를 박지 않고 **컨트롤 높이를 토큰화**
(`--h-sm` / `--h-md`)해서 버튼과 같은 값을 보게 했다 — D2.8 에서 세운 규칙
(「새 값은 토큰부터」)을 그대로 탄 첫 사례다.

vitest **155개** (+5). 목록 순서를 손으로 적어 두고 **그게 정말 내림차순인지 기계로도**
확인한다(`[...names].sort()` 와 비교) — 서비스를 추가하다 순서를 흐트러뜨리면 잡힌다.

## 2. 「지우는 중인데 값이 바뀐다」를 테스트가 닿는 곳으로

사용자가 **세션 미시작 리마인더 간격칸에서 백스페이스가 안 먹는다**고 보고했다.
값이 `3`일 때 지우면 `30`으로 되돌아가고 커서가 앞으로 밀려 더 지울 수도 없다.

**코드에는 그 버그가 없었다.** D2.8(`2eb8576`)에서 이미 `NumberField` 로 교체돼 있었고,
증상은 도그푸딩 기기에 깔린 **0.2.1 설치본(D2.6 빌드)** 의 것이었다. 진단 과정은
`docs/troubleshooting/fixed-bug-reported-again-version-skew.md`.

다만 **고칠 게 남아 있었다 — 코드가 아니라 검증이.**
「빈칸·범위 밖은 위로 올리지 않는다」는 규칙이 컴포넌트 안에만 있어서 테스트가 닿지 않았고,
그래서 **같은 버그가 두 번** 났다.

| | 언제 | 무엇을 놓쳤나 |
| --- | --- | --- |
| 1회 | D2.6 후속 | 행동 간격칸. 여기서 규칙을 만들었다 |
| 2회 | D2.8 | 리마인더칸. **clamp 함수만 통일하고 컴포넌트를 안 바꿨다** |

`liveNumber(digits, min, max): number | null` 로 빼고 회귀 케이스를 붙였다.
**동작은 하나도 바뀌지 않았다** — 컴포넌트가 인라인으로 하던 판단을 그대로 옮겼을 뿐이다.

`liveNumber` 를 일부러 망가뜨려(`return Number(digits)`) **4건이 실패하는 것까지 확인**했다.
통과만 하는 테스트를 늘리지 않으려고. vitest **160개**.

생 `<input type="number">` 잔존 grep: `NumberField.tsx` 내부 1건뿐, 다른 화면에 없다.

## 3. 0.3.0 빌드 · 설치

설치본이 **0.2.1(D2.6 빌드)로 두 Phase 뒤처져 있었다.** 버전을 세 곳
(`package.json` / `tauri.conf.json` / `Cargo.toml`)에서 올리고 빌드했다.
D2.7·D2.8 **두 Phase**가 들어가므로 패치가 아니라 마이너를 올렸다.

한 번 헛돌았다 — 17:43 에 만든 0.3.0 에는 그 뒤의 AI 드롭다운이 안 들어가 있었다.
**아직 배포된 적이 없는 번호라** 같은 0.3.0 으로 산출물만 다시 만들었다.

설치 절차 (전부 자동, 관리자 권한 불필요):

1. 실행 중이던 0.2.1 종료 → **그 다음에** DB 복사 (WAL 체크포인트 반영)
2. `HourStep_0.3.0_x64-setup.exe /S` (무인, per-user)
3. 실행 후 확인 — 버전 `0.3.0`, 창 3개 생성, 메모리 32MB

마이그레이션 v4 적용됐고 행동·기록·통계·테마 전부 남았다.
메인 창 캡처로 확인(`Phase D2.8` 배지 + 새 스타일 + 오늘 4시간 44분/7회).

### 알아둘 것 — 구버전이 설정 행을 되돌려 놓는다

0.2.1 로 지내는 동안 `settings` JSON 이 **D2.6 모양으로 덮어써졌다.**
그 빌드에는 알림음 설정이 없어서 두 필드가 통째로 빠졌다.

```json
{"idleReminderEnabled":true,"idleReminderMinutes":3,"theme":"light"}
```

0.3.0 의 `normalizeSettings()` 가 기본값(켜짐 / 60)으로 채우므로 실사용 영향은 없다 —
0.2.1 에는 볼륨을 바꿀 UI 자체가 없었으니 잃은 값도 없다. 다만 **구버전을 다시 띄우면
같은 일이 반복된다.** dev 와 설치본이 같은 DB 를 쓰는 구조의 연장선이다
(`docs/troubleshooting/dev-and-installed-share-db.md`).
