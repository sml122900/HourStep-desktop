원천 자료 2개(`docs/content/hourstep-evidence-archive.md`,

## 1. 신체정보 + 2. 물 참고 기준

`src/core/waterGoal.ts` 순수 함수. KDRIs 2020 확정치가 있는 조합(남 19-29=1,200mL,
여 50-64=1,000mL)만 mL 을 병기하고, 나머지 4조합·65세 이상·미입력은 전부
"하루 5~6잔(200mL 기준)" 단순화 문구로 뺐다 — 원문 표 미확인 칸을 지어내지 않는다는
아카이브 지침 그대로.

`suggestWaterInterval(liquidMl, sessionHours)` 은 액체 기준 ÷ 세션시간 ÷ 200mL 로 분을
낸다. 아카이브 예시(1.2L/8h→80분)와 정확히 일치하는 걸 vitest 로 확인했다. 세션 길이를
실측하지 않으므로 **8시간(아카이브 예시와 같은 값)을 기본으로 고정**했다 — 하루 근무
길이를 추적하는 기능이 없어서 임의로 만들지 않고 아카이브가 이미 쓴 숫자를 그대로 썼다.

신체정보는 `settings` JSON 블롭이 아니라 새 `profile` 테이블(싱글턴 행)에 뒀다. 이유는
`docs/decisions/0012`. 체중 등은 수집하지 않는다(성별·연령대만, 둘 다 선택 입력).

## 3. 동작 로테이션

`src/core/actionRotation.ts` — 동작 카드 원고 8종(A1~C2)을 로테이션 순서
(A1→B1→B2→C1→A2→B3→B4→C2, 원고의 「배치 제안」 그대로) 그대로 데이터화했다.
상태(마지막 인덱스)는 `behaviors.action_index` 컬럼(마이그레이션 v5, `docs/decisions/0012`)에
저장되어 세션·재시작을 넘어 이어진다.

스트레칭 카드는 D2.9 부터 `Behavior.message` 를 읽지 않는다 — 오버레이가 대신
`actionAt(actionIndex)` 로 오늘의 동작(이름 + 방법 첫 줄, 540×139 제약 때문에 한 줄만)을
보여준다. [자세히] 버튼은 새 Rust 커맨드 `show_action_detail` 로 메인 창을 띄우고
`main://action-detail` 이벤트에 동작 id 를 실어 보낸다 — 방법 전체·시간·출처는 그 이벤트를
받은 메인 창의 새 상세 패널(`ActionDetailCard`)이 원고 그대로 보여준다.

**해소 (같은 날 수정본 반영):** 최초 배포분에서는 동작 카드 원고의 B2·B4 출처가
"동일 (…)" 로 되어 있어 우려로 지적했었다 — 로테이션 순서(…C1→A2→B3→B4→C2)에서 B4 는
B1 바로 뒤가 아니라서, 상세 화면에 B4 만 펼치면 "동일"이 무엇과 동일한지 알 수 없었다.
수정본에서 B2·B3·B4 출처를 B1 과 같은 문장(Clin Rehabil, 2016)으로 통일하고, C2 도
"OSHA" → "미국 산업안전보건청(OSHA)"로 풀어 썼다(C1 과 표기 통일). 로테이션 로직·DB
값(`action_index`)은 콘텐츠 문구와 무관해 변경하지 않았다 — `docs/content/hourstep-action-cards.md`
와 `src/constants/strings.ts` 의 `ACTION_CARDS` 만 교체.

## 4. 눈·물 카드 문구 교체

`BEHAVIOR_MESSAGE.eyes`/`water` 를 각각 D1/E1 원고의 **첫 줄**로 바꿨다(전체 문장 중 카드가
보여줄 수 있는 건 한 줄뿐이라 나머지 줄은 신지 않았다 — 문장을 새로 짓지 않고 원문 한
줄을 그대로 잘라 썼다). `is_builtin=true` 인 시드 값에만 해당하고, DB 에 이미 있는 사용자
편집·기존 설치본의 문구는 건드리지 않는다 — 「기본값 복원」을 눌러야 새 문구로 바뀐다
(기존 사용자 편집을 마이그레이션으로 덮어쓰지 않는다는 원칙, `docs/decisions/0007` 과 같은 결).
