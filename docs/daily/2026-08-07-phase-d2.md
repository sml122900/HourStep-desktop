## 1. SQLite 영속화

`tauri-plugin-sql` + 마이그레이션 v1. 스키마는 Rust(`src-tauri/src/db.rs`)가 소유하고
읽기/쓰기는 TS 어댑터(`src/data/db.ts`)만 한다. `src/core/` 는 여전히 IO 금지.

**왜 Rust 가 아니라 TS 가 DB 를 쓰는가**: 세션 런타임이 이미 오버레이 웹뷰에 있다(D1 결정).
Rust 가 세션 행을, TS 가 로그 행을 쓰면 트랜잭션 경계가 두 언어에 걸친다. 쓰기 지점을
한 계층으로 모으는 편이 낫다고 봤다. Rust 는 `session://changed` 를 방송하고 TS 가 받아 쓴다.

스키마에 `occurrence_id` 를 추가했다(요청 목록에는 없던 열). `at`(액션 시각)과
`dueAt`(예정 시각)이 달라서, 이 열이 없으면 도메인 타입 `CompletionLog.occurrenceId` 를
DB 에서 복원할 수 없다.

### 강제 종료 복구

앱이 강제 종료되면 `ended_at IS NULL` 세션이 남고, 통계에서 "지금도 진행 중"으로 잡혀
작업시간이 무한정 늘어난다. 기동 시 **그 세션의 마지막 기록 시각**으로 닫는다.

여기서 경합을 하나 잡았다. 정리 쿼리와 새 세션 생성이 둘 다 비동기라, 기동 직후 사용자가
바로 [작업 시작]을 누르면 **정리가 방금 만든 살아 있는 세션까지 닫을 수 있다.**
`closeDanglingSessions(bootedAt)` 으로 "부팅 시각보다 먼저 시작된 것만" 닫도록 했고,
어댑터 초기화 순서도 `정리 → 설정 로드 → 현재 세션 확인` 으로 직렬화했다.

## 2. 통계

`src/core/stats.ts` 순수 함수 + vitest 15개. `now` 와 구간은 인자 주입.
"오늘 0시" 는 타임존이 필요해 순수하지 않으므로 `src/data/range.ts` 에 뒀다
(DST 로 하루가 23/25시간일 수 있어 `+86400000` 이 아니라 날짜를 더해 계산한다).

설계에서 신경 쓴 두 가지:

- **자정을 넘는 세션은 구간과 겹치는 부분만 센다.** 22시~새벽 2시 세션이 "오늘" 통계에
  4시간으로 잡히면 안 된다
- **실천율 0% 와 "기록 없음"을 구분한다.** `rate: number | null` 로 두고 null 은 `—` 로 표시.
  0% 로 뭉개면 "전부 건너뛴 날"과 "쉬는 날"이 같아 보인다

메인 창은 오늘/최근 7일 두 패널. 데이터 0건이면 안내 문구로 대체된다.

## 3. 설정 창

행동별 on/off + 간격(분), 미시작 리마인더 on/off + 분, 기존 autostart 토글.
저장소는 SQLite `settings` 테이블 — 근거는 `docs/decisions/0003`.

저장·방송을 어댑터의 `saveSettingsAndBroadcast()` 한 함수로 모았다. 설정 창과
`--debug-cmd set-interval` 이 **같은 함수**를 타야 자동 검증이 의미를 갖기 때문이다.
저장이 실패하면 방송하지 않는다 — 화면·DB·스케줄이 갈라지면 안 된다.

입력 검증: 설정 창은 신뢰 경계다. 숫자 칸을 비우면 `NaN` 이 들어오고, DB 가 손상되거나
구버전일 수도 있다. `normalizeSettings()` 가 범위 밖·타입 불일치·프리셋에 없는 항목을
전부 정리한 값만 저장한다. 설정 JSON 파싱이 실패해도 기본값으로 살아난다 — 설정 파일
하나 깨졌다고 앱이 안 켜지면 안 된다.

## 4. 세션 미시작 리마인더

세션 없이 N분(기본 30) 지나면 오버레이 카드 1회. [▶ 작업 시작] 은 트레이 메뉴와 같은
핸들러를 탄다. 세션이 시작되거나 종료될 때 플래그가 리셋되므로 "유휴 구간당 한 번" 이다.

## 실측 (자동 검증, 합성 입력 없음)

vitest 47개 (scheduler 16 / stats 15 / settings 11 / overlayPosition 5).

### DB write → 재시작 → read

```
1회차: [debug] db sessions=0 open=0 workedMs=0 logs=0 done=0     ← 빈 DB
       … start-session → tick 30분 → done → tick 20분 → skipped → end-session
       [debug] db sessions=1 open=0 workedMs=3014001 logs=2 done=1
2회차(프로세스 재시작): [debug] db sessions=1 open=0 workedMs=3014001 logs=2 done=1
```

### 설정 즉시 반영

```
start-session → set-interval:water=5 → [debug] settings water.everyMinutes=5
tick:300000(5분) → dump overlay.visible=true → done → log behavior=water
```

기본 30분이면 5분 시점에 뜰 수 없다. 실행 중 세션의 스케줄이 다시 계산됐다는 뜻.

### 강제 종료 복구 + 경합

```
1회차: end-session 없이 quit → open=1 (미종료 세션 남음)
2회차: 기동과 동시에 start-session
       [debug] db sessions=6 open=1 workedMs +1804993   ← 옛 세션은 닫히고(+30분)
       dump session.active=true elapsedMs=13002         ← 새 세션은 살아 있다
```

### 미시작 리마인더

```
tick 30분 → [overlay] action = idle-reminder, visible=true
닫고 다시 tick 30분 → visible=false                      ← 반복 안 함
세션 시작→종료 → 다시 tick 30분 → idle-reminder 재발화     ← 유휴 구간당 1회
```

### D1 e2e 회귀

D1 시나리오 전부 통과. **한 군데만 의도적으로 달라졌다** — `end-session` 후
`overlay.visible` 이 D1 에서는 `false` 였는데 D2 에서는 요약 카드 때문에 `true` 다.
요약을 닫으면 `false`. 회귀 스크립트를 그에 맞게 갱신했다.
