## 왜

D2.5 에서 색을 CSS 변수로 옮겼지만 규격 문서가 없어 창마다 값이 갈렸다. 착수 시점 실측:

- 같은 성격의 버튼이 **네 벌** — `.ghost`(메인) / `.chip`(설정) / `.btn`(오버레이) / `.session__toggle`
- 반경 **8종** (6·7·8·9·10·12·14·18px), 글자 크기 **12종** (11~34px, 12.5px 포함)
- 여백이 4px 격자를 벗어난 값 다수 (22·26·9·5·3·1px)

## 한 것

### 1. 토큰 (`src/styles/tokens.css`)

색·간격·반경·그림자·타이포·모션을 두 벌(다크 기본 / 라이트)로 정의했다.
**두 벌의 토큰 이름 집합이 같아야 한다**는 규칙을 테스트로 걸었다 — 한쪽에만 있으면
그 테마에서 조용히 다른 테마 값을 물려받는다.

`base.css` 가 `tokens.css` 와 `components.css` 를 `@import` 하므로 창별 `main.tsx` 는
`base.css` 하나만 읽으면 된다 (엔트리 3개를 안 건드렸다).

**대비를 실측해서 세 곳을 고쳤다** (WCAG AA 본문 4.5:1):

| 조합 | 이전 | 지금 |
| --- | --- | --- |
| 다크 `--text-subtle` on 패널 | #6f768a → 3.68 ✗ | #868ea2 → 5.08 ✓ |
| 라이트 `--text-subtle` on 창 배경 | #838b9d → 3.10 ✗ | #636b7e → 4.85 ✓ |
| 흰 글자 on 주 버튼 | 그러데이션 상단 #5b93ff → 2.9 ✗ | #2f6fe0 → 4.70 ✓ |

주 버튼의 세로 그러데이션(`--accent-grad`)을 없앴다. `--accent-hover` 라는 토큰과
같이 갈 수 없고, 두 정지점 중 밝은 쪽이 흰 글자와 3:1 도 못 넘겼다.
이제 `--accent` 는 라이트/다크가 같은 값이고, 어두운 배경 위의 **글자용** 강조색은
`--accent-text` 가 따로 맡는다.

### 2. 공통 컴포넌트 (`src/components/`)

`Button` / `NumberField` / `Checkbox` / `Card` / `Section` / `EmptyState`.
`src/windows/settings/NumberInput.tsx` 는 `components/NumberField.tsx` 로 올라갔다.

**Toggle 은 만들지 않았다.** 이 앱의 on/off 는 전부 체크박스이고, 스위치를 쓰는 자리가
하나도 없다. 쓰이지 않는 컴포넌트는 죽은 코드다 (design-system.md 에 이유를 적어 뒀다).

`.btn` 이 세 창에서 다 성립해야 해서 보조 버튼 배경을 **반투명 토큰**(`--bg-sunken` /
`--bg-hover`)으로 잡았다. 불투명 색이면 오버레이 카드 위에서 사각형 얼룩이 된다.

### 3. 리마인더 간격칸에 남아 있던 버그

D2.6 후속에서 행동의 간격칸에 고쳤던 「마지막 글자를 지우면 값이 되돌아간다」가
**세션 미시작 리마인더 칸에는 그대로 남아 있었다.** 거기만 생 `<input type=number>` 라
`Number('')=0` 이 저장되고 `normalizeSettings` 가 손상으로 보고 기본값 30분으로 되돌렸다.
`NumberField` 로 통일하면서 `clampIdleReminderMinutes()` 를 추가해 같은 규칙을 태웠다.

### 4. 자동 검증 (`src/styles/tokens.test.ts`)

- 토큰 밖 CSS 5개 파일에 색 리터럴 **0건**
- 그 파일들의 `padding`/`margin`/`gap` 이 전부 `var(--sp-*)` · `0` · `%` · `calc(토큰)`
- `overlay.css` 에 `--shadow-*` 없음 (창이 카드 실크기라 그림자가 잘린다)
- 두 테마의 토큰 이름 집합 일치 / 검사 대상 파일 목록 일치

stylelint 를 들이지 않았다. 규칙 네 개에 의존성·설정 파일이 늘어난다.

vitest **150개** (+ tokens 14 / sanitizeDigits 5 / clampIdleReminderMinutes 3).

### 캡처 4화면 × 라이트·다크 = 8장

`CopyFromScreen`, 대상 창을 일시 topmost 로 올려 그 사각형만. 합성 입력은 쓰지 않았다.
스크립트는 스크래치패드(`capture.ps1`), 결과는 `…/scratchpad/shots/`.

세 번 걸렸고 전부 자동 검증 쪽 문제였다 (상세: `docs/troubleshooting/window-capture-pitfalls.md`):

1. **자식 `powershell -File` 프로세스에서는 데스크톱 창이 안 보인다.** `FindWindow`·
   `EnumWindows` 가 0을 돌려준다. 도구가 여는 PowerShell 세션 **안에서**(`& script.ps1`)
   돌려야 한다
2. **WebView2 가 같은 제목의 160×28 보조 창을 띄운다.** 제목만 보고 찾으면 그걸 잡는다.
   같은 제목 중 **가장 큰** 창을 고르게 고쳤다
3. 벽시계 기준 스케줄이 계속 어긋났다(메인 창은 **부팅 때 이미 보인다** — `main-show` 를
   기다린 줄 알았는데 부팅 창을 잡고 있었다). 결국 **상태를 기다리는** 방식으로 바꿨다:
   보임→숨김→보임 세 전이를 다 통과해야 앵커로 인정하고, 그 다음부터는 창이 뜨는 것을 보고 찍는다

### 캡처가 잡은 회귀 — 설정 창 가로 스크롤

D2.8 적용 후 설정 창에 **가로 스크롤바**가 생겼다. 기준선(변경 전)을 `git stash` 로
따로 캡처해 비교해서 D2.8 이 만든 것임을 확인했고, 임시 폭 프로브를 심어 원인을 특정했다.

```
PROBE shellClient=545 shellScroll=564   li=540  row=514   ← 고치기 전
PROBE shellClient=545 shellScroll=545   li=497  row=471   ← 고친 뒤
```

원인은 아이콘 버튼이 24→28px 로 커진 것 **자체가 아니라**, `.behavior` 의 암묵 그리드
트랙이 `auto`(최대치 = max-content)라서 **안쪽 입력칸들이 각자 요구하는 기본 폭(≈20자)의
합만큼 부풀고, 컨테이너보다 커져도 줄지 않는다**는 데 있었다. 원래도 여유가 0에 가까웠고
D2.8 이 28px 를 더 얹어 넘겼다. `grid-template-columns: minmax(0, 1fr)` 로 최소를 열어
주니 창 폭에 맞고, 남는 자리는 이름칸이 흡수한다. 창을 좁혀도 이제 안 깨진다.
