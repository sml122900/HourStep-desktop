# 2026-08-08 — Phase D2.6: AI 검색 브리지 (구글 딥링크 + 붙여넣기 파서)

D2.5 로 행동을 "만들 수는" 있게 됐지만, 무엇을 몇 분마다 해야 하는지는 여전히 사용자가
지어내야 했다. 그 지식이 없어서 앱을 켠 건데. D2.6 은 그 간극을 **서버·API 키·계정 없이**
메운다 — 앱이 질문을 만들어 브라우저를 열고, 답은 사용자가 복사해 온다.

설계 근거는 `docs/decisions/0008`. 요약: **앱은 구글 결과를 직접 읽지 않는다.**

## 1. 프롬프트 생성 + AI 이동 (`src/core/aiQuery.ts`)

`buildRoutinePrompt({job, symptom})` → 프롬프트 전문, `buildAiUrl(target, prompt)` → 진입 주소.
여는 건 `tauri-plugin-opener` 의 `openUrl()` 이고 **기본 브라우저**로 간다.
앱 내 웹뷰로 AI 를 띄우지 않는다(스크래핑 오해 소지).

**프롬프트를 URL 에 태우고 끝내지 않는다.** 처음엔 구글 검색 URL 에 질의를 실어 보내는 걸로
끝냈는데 두 가지가 걸렸다 — ① 자기 증상이 담긴 문장이 URL 안에 숨어 나가서 사용자가 무엇을
보내는지 모른다 ② `q` 주입이 되는 건 구글뿐이라 다른 AI 를 쓸 수 없다.

그래서 화면 구성이 세로 3단이 됐다: ① 프롬프트 전문(접지 않는다) + 「📋 복사」
② AI 열기 버튼 3개 ③ 결과 붙여넣기. **이동 시 클립보드에 자동으로 넣는다** — 복사 없이
이동하면 붙여넣을 게 없어 기능 자체가 무의미하다. 구글도 예외로 두지 않았다(URL 에 이미
실려 있어도 다시 붙여넣을 수 있어야 한다).

`AI_TARGETS` 는 `injectsPrompt` 플래그를 들고 있고, 안 되는 대상은 버튼 문구가
「ChatGPT 열기 (붙여넣기 필요)」로 바뀐다. 기대를 어긋나게 하지 않는 쪽이 낫다.
**주소는 `TARGET_URL` 한 곳에만** 적는다 — 서비스 도메인은 바뀐다.

클립보드는 `navigator.clipboard` 가 아니라 `tauri-plugin-clipboard-manager` 다. 웹뷰의
클립보드 API 는 보안 컨텍스트·포커스 조건에 걸려 패키징 후 **조용히** 실패할 수 있다.
권한도 `allow-write-text` 만 줬다 — 읽기는 필요 없다(붙여넣기는 사용자가 직접 한다).
그래도 복사가 실패하면 안내만 남긴다. 프롬프트 전문이 화면에 있으니 직접 선택해 복사하면 된다.

프롬프트 끝의 출력 형식 지시는 사용자가 쓴 문구 그대로다(규칙 8). 블록 표식은 파서와
**같은 상수**(`BLOCK_OPEN`/`BLOCK_CLOSE`)를 쓴다 — 한쪽만 바뀌면 파싱이 통째로 실패한다.

길이는 **조립 후 자르지 않고 입력을 먼저 자른다**. 형식 지시가 프롬프트 **끝**에 있어서,
뒤를 자르면 잘리는 게 하필 그 지시다. 직군 40자 / 증상 120자로 막으면 전체 길이가
결정론적으로 묶인다(테스트가 지킨다).

사용자 입력에서 `[HOURSTEP]` / `[/HOURSTEP]` 을 지우고 줄바꿈을 눌러 넣는다. 안 그러면
입력에 표식을 섞어 형식 지시를 두 겹으로 만들 수 있다.

## 2. 파서 (`src/core/routineParse.ts`)

JSON 을 요구하지 않은 이유가 이 파일의 전제다. AI 는 JSON 을 코드펜스로 감싸고 주석을 달고
후행 쉼표를 남긴다 — `JSON.parse` 는 그 중 하나만 어긋나도 **전부** 실패한다. 파이프 구분
줄은 줄 단위로 실패해서 나머지를 살릴 수 있다.

실제로 흡수하는 것들: 코드펜스 / 마크다운 볼드·인라인 코드 / 불릿·번호 목록 /
마크다운 표(`| a | b | c | d |`) / 전각 파이프 `｜`·박스 드로잉 `│` / `"30분마다"`·`"45 min"`.

정한 것 몇 가지:

- **블록이 여러 개면 항목이 나오는 마지막 블록**을 쓴다. AI 는 형식을 설명하며 빈 템플릿을
  먼저 따라 쓰는 일이 잦고, 질의가 "답변 마지막에 정리해줘"라고 요구한다
- 템플릿 예시 줄(`이모지|행동이름|…`)은 건너뛰되 **형식 오류로 세지 않는다** — 사용자 잘못이
  아닌데 "1줄 건너뜀"이라고 알리면 혼란만 준다
- 표 양끝의 빈 칸은 **5칸 이상일 때만** 걷어낸다. 이미 4칸이면 손대지 않는다 —
  이모지 칸이 빈 정상적인 줄(`|물마시기|30|문구`)을 표로 오인하면 그 줄이 통째로 날아간다
- 간격은 `-?\d+` 로 뽑는다. 부호를 안 잡으면 `"-5"` 가 `5` 로 둔갑한다
- 실패 사유는 문장이 아니라 **코드**(`no-block` / `empty-block` / `partial`)로 돌려준다.
  한국어 카피는 UI 상수가 소유하고 코어는 판정만 한다

이름·문구 상한이 **두 겹**인 게 유일하게 헷갈릴 만한 부분이다. 파싱 상한(30자/120자)은
"이 줄이 행동 이름이 맞는가"를 판별하는 기준이고 — 문단 하나가 통째로 들어오면 그건 행동이
아니다 — 저장 상한(24자/80자)은 "카드에 들어가는가"다. 그래서 조금 긴 건 **잘라서 살리고**
터무니없이 긴 건 버린다. 잘린 값은 미리보기에 그대로 보이므로 저장된 것과 화면이 갈라지지 않는다.

vitest 31개 추가 (routineParse 20 / aiQuery 11). 스펙이 요구한 필수 케이스 —
블록 없음 / 블록 여러 개 / 코드펜스 / 전각 파이프 / 볼드 혼입 / `"30분"` / 빈 블록 — 전부 포함.

## 3. 미리보기 → 삽입 (`src/windows/settings/RoutineFinder.tsx`)

설정 창에 섹션 하나를 더 붙였다(새 창을 만들지 않았다 — 행동 편집이 이미 여기 있다).

**파싱 실패를 에러로 끝내지 않는다.** 실패하면 붙여넣은 원문(textarea)을 그대로 둔 채 빈
입력 줄을 하나 띄운다. 그래서 성공·실패의 이후 경로가 **완전히 같다** — 미리보기 줄을
체크·수정하고 [추가]를 누르면 들어간다. 폴백을 위한 별도 화면이 없다는 게 요점이다.

직삽입 경로는 없다. 파싱 결과는 아직 행동이 아니라 `RoutineItem` 이고,
`routineItemsToBehaviors()` → `saveBehaviorsAndBroadcast()` 로만 행동이 된다. 손으로 추가할
때와 **같은 함수**라 실행 중 세션에 즉시 반영된다(D2.5 CRUD 경로 그대로).

미리보기에는 고지 한 줄이 고정으로 뜬다: "참고용이며 전문의 상담을 대체하지 않습니다."
우리가 문구를 지어내지 않는다는 것과 짝이 되는 장치다(규칙 6).

## 4. `source` 컬럼 — 마이그레이션 v3

스펙에는 "source='ai' 로 저장 (D2.5 컬럼 재사용)"이라고 적혀 있었지만 **그런 열은 없었다.**
D2.5 가 만든 건 `is_builtin` 이고, 그건 "내장 3종이냐"는 다른 사실이자 근거 기반 프로토콜을
붙일 자리다(0007). 겸용하면 둘 중 하나는 반드시 어긋난다.

→ 마이그레이션 v3 로 `source TEXT NOT NULL DEFAULT 'user'` 추가. `Behavior.source` 는
`'user' | 'ai'` 두 값뿐이고 `'builtin'` 은 넣지 않는다(같은 사실을 두 곳에 적지 않는다).
기존 행은 DEFAULT 로 채워지고, 값 검증은 늘 그렇듯 `normalizeBehaviors()` 가 한다.

설정 목록에서 AI 유래 행동에는 `AI` 태그가 붙는다.

## 5. 간격 입력칸 (2026-08-09 후속)

설치본으로 도그푸딩하다 나온 것. 간격칸에서 마지막 한 글자를 지우면 값이 `0`으로 튀고,
저장 시 정규화가 "범위 밖"으로 판단해 시드 간격으로 되돌려 버렸다. **지우는 중일 뿐인데
값이 바뀐다.** `value={숫자}` 로 두고 `Number(e.target.value)` 를 바로 쓴 게 원인이다.

`IntervalInput` 으로 분리했다. 입력 중에는 **문자열**을 들고(빈 문자열 허용), 범위 안의 값일
때만 위로 커밋하고, 포커스가 빠질 때 경계로 복구한다(빈칸 → 1, 500 → 480).
설정 목록과 AI 미리보기가 같은 컴포넌트를 쓴다.

두 가지를 더 붙였다.

- 복구 규칙은 `clampIntervalMinutes()` 순수 함수로 코어에 두고 테스트했다(+3). 기존
  `clampMinutes` 와 다르다 — 그건 범위 밖을 **시드로 되돌리고**, 이건 **가까운 경계로 붙인다**.
  저장된 값을 고치는 것과 입력 중인 값을 고치는 건 놀라움의 크기가 다르다
- 밖에서 값이 바뀌면(「기본값 복원」·다른 창·`--debug-cmd`) 따라가되, **입력 중이면 안 따라간다**.
  안 그러면 타이핑하던 값이 방송에 덮인다

### 배포 — 설치본 0.2.0 → 0.2.1

`pnpm tauri build` → NSIS/MSI 2종, NSIS 를 `/S` 로 설치. 확인은 레지스트리
`DisplayVersion` + exe `FileVersion` + 자동실행 등록 + 실행 후 `MainWindowTitle`.
버전을 올린 이유는 단순하다 — **0.1.0 그대로 두면 어느 빌드가 깔려 있는지 알 수 없다.**
태그·릴리스 배포는 하지 않았다(규칙 7).

설치 전에 **진행 중 세션이 있는지 먼저 확인**했다(`ended_at IS NULL` 조회). 있는데 강제
종료하면 그 세션은 기동 시 마지막 기록 시각으로 닫혀 작업시간이 깎인다.

## 사고 기록 — 검증하다 사용자 설정을 날렸다 (2026-08-09)

간격 입력칸을 고친 뒤 `behaviors-dump` 에 시드와 다른 값(30/30 + 뒤바뀐 순서)이 찍혔다.
**방금 만진 코드가 값을 망가뜨렸다고 단정**하고 원인을 좁히려 `behavior-restore` 를 돌렸다.
그 순간 사용자가 설치본에서 직접 편집한 값이 시드값으로 덮여 사라졌다.

값은 코드가 아니라 사람이 바꾼 것이었고, 그 근거가 이미 로그에 있었다.

- 그 값은 실행이 **시작될 때 이미 DB 에 있었다**(첫 덤프에 그대로) → 그 실행 중에 생긴 게 아니다
- **순서가 바뀌어 있었다.** 순서는 설정 창의 ↑/↓ 로만 바뀐다 → 사람 손이 닿았다는 뜻

되돌릴 때 간격 두 개와 순서는 로그를 근거로 복구했지만, **물마시기 값 하나는 복구하지
못했다** — 조사 중 `set-interval:water=45` 를 먼저 실행해 원래 값이 어느 로그에도 남지
않았다. 순서 복구 경로가 없어 `--debug-cmd behavior-move:<id>=<up|down>` 을 이때 추가했다.

배운 것 두 가지. **dev 와 설치본은 같은 DB 를 쓴다** — 모든 `--debug-cmd` 검증은 사용자
데이터에 대고 하는 것이다. 그리고 **덤프를 검증 스크립트 맨 앞에도 넣어야 한다** — "원래
이랬는지 내가 바꿨는지"를 나중에 판별할 유일한 근거다.
절차와 파괴적 명령 목록은 `docs/troubleshooting/dev-and-installed-share-db.md` 에 적었다.

## 남은 것 / 알아둘 것

- **물마시기 간격이 사용자가 쓰던 값인지 확인 필요.** 위 사고로 복구하지 못해 시드값
  30분을 넣어뒀다 (스트레칭·눈휴식 30분과 순서는 로그로 확인된 값)
- **눈으로 볼 것**: ① AI 열기 버튼 3개가 실제로 기본 브라우저에서 각 서비스를 여는가
  (클립보드에 들어가는 것까지는 훅으로 확인했다) ② 진짜 AI 답변을 붙여넣었을 때 파싱이
  통하는가(샘플이 아닌 실물) ③ 프롬프트 영역이 읽을 만한 크기인가(현재 190px 에서 스크롤)
- 파서가 실물 답변에서 자주 실패하는 패턴이 보이면 `strip()`/`PIPE` 에 흡수 규칙을 더한다.
  실패해도 수동 입력으로 이어지므로 사용자가 막히지는 않는다
- 질의문에 "행동이름은 10자 이내, 알림문구는 40자 이내로" 를 넣어 저장 상한(24/80)에
  걸려 잘리는 일을 줄였다. 그래도 넘치면 잘린 값이 미리보기에 그대로 보인다
- 카드 문구의 연구 인용은 **여전히 없다**. AI 가 근거를 말해줘도 그건 사용자가 본 것이지
  우리가 검증한 출처가 아니다 — `is_builtin` 자리는 그대로 비워 둔다(규칙 6)
