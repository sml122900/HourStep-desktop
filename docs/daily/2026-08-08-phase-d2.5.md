# 2026-08-08 — Phase D2.5: 메인 화면 + 커스텀 행동 + 테마

D3(전체화면 감지·다중 모니터) 전에 도그푸딩 가능한 UX 로 만드는 단계.
트레이에서만 되던 조작이 메인 창으로 나왔고, 하드코딩 프리셋 3종이 사용자가
만들고 지우는 행동 목록이 됐고, 라이트 모드가 붙었다.

## 1. 메인 화면에서 세션 시작/종료

`end_session_command` 를 추가하고 메인 창에 토글 버튼을 달았다. 트레이 메뉴와
**같은 `session::start/end`** 를 부르므로 라벨 동기화는 공짜다 — 어느 쪽에서 눌러도
`tray::set_session_active` + `session://changed` 한 줄기로 합쳐진다. 폴링 없음.

## 2. 타이머 표시 — `app://tick` 을 모든 창으로

메인 창에 경과시간·다음 알림 카운트다운·예정 목록을 넣었다. 계산은 오버레이가 쓰는
`computeNextOccurrences` 를 그대로 재사용한다.

**`Date.now()` 를 안 쓴 이유**가 이 항목의 핵심이다. 원래 1초 tick 은 오버레이에만
보냈고(D1 결정 0004) "메인 창까지 매초 깨울 이유가 없다"고 적어뒀었다. 이제 이유가
생겼다 — 메인 창이 벽시계를 보면 `--debug-cmd tick:` 의 가상 시각과 갈라져서
"표시값과 실제 발화가 맞는가"를 검증할 방법이 사라진다. `emit_to(OVERLAY)` 를
`emit()` 으로 바꾸고, 숨어 있는 창은 `document.hidden` 으로 렌더를 건너뛴다.

통계도 매 tick 다시 계산한다. 순수 함수라 공짜고, DB 재조회만 30초 주기로 남겼다.

## 3. 행동 커스터마이징

프리셋 하드코딩 → `behaviors` 테이블(마이그레이션 v2). 근거는 `docs/decisions/0007`.

- `Behavior` 에 `message` / `isBuiltin` / `sortOrder` 추가
- `src/core/behaviors.ts` 신설 — 정규화·순서 이동·「기본값 복원」·레거시 흡수 전부
  IO 없는 순수 함수 (vitest 27개)
- `src/core/presets.ts` 는 시드 전용으로 축소. 문구는 여전히
  `src/constants/strings.ts` 에서 가져온다 (규칙 8)
- `applySettings()` 삭제. 스케줄러에 넘길 목록은 `db.loadBehaviors()` 하나뿐이다
- `computeNextOccurrences` 는 손대지 않았다 — 원래부터 `Behavior[]` 주입 구조였다

### 삭제된 행동의 과거 기록

`completion_logs.behavior_label` 에 기록 시점 이름을 스냅샷한다. FK + `ON DELETE SET NULL`
을 버린 이유는 `docs/decisions/0006` — 요약하면 SET NULL 은 **행동별 집계 자체를**
되돌릴 수 없게 날린다. 통계가 D2 의 결과물인데 D2.5 의 삭제 기능이 그걸 지우면 안 된다.

### 이모지 자르기

이름·문구·이모지 상한을 코드포인트 단위로 자른다. `String.slice` 를 쓰면 서로게이트
페어가 반으로 갈려 이모지가 `U+FFFD` 로 깨진다. 테스트로 박아뒀다.

## 4. 라이트 모드

색을 전부 `src/styles/base.css` 토큰으로 뽑고 창별 CSS 는 토큰만 참조하게 했다.
`:root` 기본값은 다크로 두고 `[data-theme='light']` 가 덮는다 — 창이 만들어진 직후
JS 가 속성을 붙이기 전 한 프레임에 흰 화면이 번쩍이지 않게.

`src/windows/theme.ts` 를 세 창이 각자 한 번 부른다. 저장된 선호 + OS 상태 →
실제 테마 결정은 `src/core/theme.ts` 순수 함수.

**오버레이 카드의 라이트 대비**가 유일한 실질 문제였다. 창이 카드 실크기라 드롭섀도를
못 쓰는데(0005), 밝은 배경 위 흰 카드는 경계가 사라진다. 라이트 토큰에서만 테두리를
`rgba(15,23,42,0.26)` 으로 진하게 잡고 안쪽 그림자로 아래 가장자리를 눌렀다.
캡처로는 문서·에디터 위에서 경계가 보인다 — 다만 지각 판단은 사용자 몫이다.

## 검증

전부 `--debug-cmd` 훅. 합성 입력 없음. 훅에 `main-dump` / `behaviors-dump` /
`behavior-add|delete|restore` / `set-theme` 를 추가했다.

### 마이그레이션 v1 → v2

실제 도그푸딩 DB(v1, 세션 1건)를 백업하고, 흡수가 눈에 보이도록 설정 JSON 에
`물마시기 13분 / 눈휴식 off` 를 심은 뒤 올렸다.

```
[debug] behaviors n=3 0:stretch(🧘스트레칭,50m,on,builtin) 1:water(💧물마시기,13m,on,builtin) 2:eyes(👀눈휴식,60m,off,builtin)
[debug] db sessions=1 open=0 workedMs=0 logs=0 done=0 labeled=0 behaviors=3 enabled=2
```

기존 세션 보존 ✓ / D2 설정 흡수 ✓ / 강제 종료로 남았던 미종료 세션도 기동 시 닫힘 ✓

### 타이머 표시값 = 실제 발화 시각

```
[debug] main now=1786174460607 elapsedMs=1990 next=water@1786176258617 remainingMs=1798010
[debug-cmd] dump session.active=true startedAt=1786174458617 elapsedMs=1805001
[debug-cmd] dump overlay.visible=true
[session] log behavior=water action=done at=1786176263609
```

`startedAt + 30분 = 1786176258617` — 메인 창이 예고한 값과 실제로 뜬 카드가 일치.
완료 후 메인 창의 다음 알림은 `stretch@1786177458617`(= startedAt + 50분)로 넘어갔다.

### 행동 CRUD 가 실행 중 세션에 즉시 반영

```
[debug] behavior add jump n=4
[debug] main now=… elapsedMs=3992 next=jump@1786174924070   ← startedAt + 7분
[debug-cmd] dump overlay.visible=true                        ← 7분 뒤 실제 발화
[session] log behavior=jump action=skipped
[debug] behavior delete jump n=3
[debug] settings water.everyMinutes=5
[debug] main now=… elapsedMs=432996 next=water@1786175104070 ← startedAt + 10분(=2×5분)
```

추가·삭제·간격 변경 모두 세션을 끊지 않고 다음 tick 부터 반영됐다.
`labeled=2` — 두 기록 모두 이름 스냅샷이 들어갔고, `jump` 는 삭제 후에도
메인 창 통계에 `🧪 jump` 로 남았다.

### D1/D2 회귀

세션 미시작 리마인더(17분 유휴 → 1회) ✓ / 30분 물마시기 카드 → 스누즈 → 3분 뒤 재발화 ✓ /
세션 종료 요약 카드 ✓ / 미종료 세션 기동 시 복구 ✓

### 시각 확인

창별 캡처(`CopyFromScreen`, 대상 창을 일시 topmost 로 올려 그 사각형만)로 라이트·다크
각각 메인/설정/오버레이 3장씩. **캡처는 증거이고 최종 판정이 아니다** — 지각 확인은 남아 있다.

캡처 중 잡은 버그 하나: **설정 창이 외부 변경을 안 따라왔다.** 창은 앱 기동 때 만들어져
한 번 읽고 숨어 있다가 나중에 보이는데, 그 사이 바뀐 값을 반영하지 않아 다크 화면에
"라이트 선택됨 / 물마시기 5분"이 남아 있었다. **다시 보일 때** 읽어오도록 고쳤다.
보이는 동안 오는 방송은 무시한다 — 이 창이 유일한 편집자라 대부분 자기가 낸 방송이고,
그때 다시 읽으면 타이핑 중인 값을 덮어쓴다.

## 남은 것 / 알아둘 것

- 메인 창의 예정 목록은 **정규 스케줄 예정표**다. 오버레이가 들고 있는 스누즈와
  "이미 띄운 것"은 모르므로, 방금 지나간 한 건이 잠깐 남아 보일 수 있다
- 설정 창의 글자 입력은 blur(또는 창이 숨을 때) 저장이다. 체크박스·순서·삭제·추가는 즉시
- 행동 개수 상한 20. 넘으면 [행동 추가]가 비활성되고 안내 문구로 바뀐다
