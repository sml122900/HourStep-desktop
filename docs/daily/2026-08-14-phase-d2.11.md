# 2026-08-14 — Phase D2.11: 카운트다운 동작별 단계 타이머

배경: 도그푸딩 피드백 — 카운트다운 중 동작 방법이 텍스트로만 표시되는데, 단계별로
타이머가 돌면서 따라할 수 있으면 좋겠다는 요청. 원고 원천은 D2.9·D2.10 과 같은
`docs/content/hourstep-action-cards.md`.

## 1. 원고 — 8개 동작을 단계로 쪼갠다 (승인 기반)

기존 "방법 2줄"을 그대로 옮기되, 좌우 대칭 동작(목·손목)은 2~4단계로, 단일 동작은
1단계로 나눴다. 단계 duration 합은 v4 기본 행위 시간(60초)과 맞췄다. 임의로 새
문구를 짓지 않고 원문을 쪼개거나 방향 접두어만 붙이는 수준으로 초안을 먼저
보여주고 승인받았다:

- B1(목 기울이기): 좌 30초 / 우 30초 (원문 범위 "15~30초"의 상한을 채택 — 하한이면
  좌우 합이 30초라 60초를 못 채운다)
- C1(손목 젖히기): 4단계(위-왼쪽/위-오른쪽/아래-왼쪽/아래-오른쪽) × 15초. 처음엔
  "아래로" 두 단계에 "위로" 단계의 당기는 동작 문구를 그대로 복사해 채웠는데,
  사용자가 **원문에 없는 방향 지시를 지어낸 것**이라고 지적해 되돌렸다 — 최종은
  방향 큐 없이 `"손끝 아래로 — 왼쪽/오른쪽"` 로 최소화(원고 "아래로도 반복" 톤 유지)
- A2("2~5분")는 실제 카운트다운(60초)과 원래부터 어긋나 있었다 — 이번 기능과
  무관한 기존 불일치라 손대지 않기로 확인받았다

전체 표는 `docs/content/hourstep-action-cards.md` 「단계 분할」 절에 반영했다.

## 2. 데이터 모델 — `steps` 필드 (원고에만, DB 스키마 변경 없음)

`ACTION_CARDS`(`src/constants/strings.ts`) 각 항목에
`steps: { label, durationSec, minDurationSec? }[]` 추가. `minDurationSec` 은
**원문에 시간이 명시된 단계에만** 둔다 (B1 좌우 15초, C1 각 15초, A1 "1분간"=60초,
B4 "15~30초×2회"의 총 하한 30초). 회수만 적힌 동작(B2·B3·C2)과 이미 불일치가
확정된 A2 에는 두지 않았다.

## 3. 코어 — `src/core/actionSteps.ts` (순수 함수, IO 없음)

- `scaleSteps(steps, targetDurationSec)` — 사용자가 설정한 실제 행위 시간(가변)에
  맞춰 원고 단계를 정수 초로 재배분. water-filling 으로 `minDurationSec` 을
  지키고, largest-remainder 반올림으로 합이 정확히 목표와 같아지며 0초 단계가
  생기지 않는다. **목표가 최소 시간 합보다 짧으면 최소 시간 합을 그대로 쓴다**
  (예: C1 은 4×15=60초가 이미 floor 라서 `duration_sec` 을 8초로 줄여도 여전히
  60초를 돈다) — 근거(연구가 측정한 유지 시간)를 어기지 않는 쪽을 설정값보다
  우선한 판단. 근거는 `docs/decisions/0015`
- `currentStepAt(steps, elapsedMs)` — 경과 시간 → 현재 단계 + 단계 내 남은 시간
- vitest 13개(스케일 업/다운, floor 강제, 반올림 정확성, 경계값) +
  `actionRotation.test.ts` 에 8개 동작의 "단계 합=60초" 콘텐츠 무결성 검증 추가

## 4. UI — `OverlayWindow.tsx`

`[완료]` 로 카운트다운 진입 시 `scaleSteps` 결과를 한 번 고정해 두고
(`countdownStepsRef`), 초마다 `currentStepAt` 으로 현재 단계를 다시 계산한다.
카운트다운 중 방법 전문을 통째로 보여주던 걸 "현재 단계 라벨 + 그 단계 남은
시간(큰 숫자) + 진행바(세그먼트, 지난 단계는 채움·현재 단계는 옅게 채움)" 로
바꿨다. 눈휴식(D1)은 로테이션도 단계도 없어 기존 방식(고정 원고 전문) 그대로 둠.
진행바는 새 색 없이 기존 토큰(`--accent`/`--bg-sunken`/`--r-full`)만 사용.

## 5. 전환음 — 새로 만들지 않고 재사용

`src/windows/sound.ts` 에 `SoundCue`를 `'step'` 으로 하나 늘렸지만 **정의는
`end` 와 완전히 동일한 톤**이다 — cue 키만 나눠 stdout 로그(`sound step …`)에서
"단계 전환"과 "카운트다운 종료"를 구분할 수 있게 했을 뿐 새 소리는 없다.
C1(손목)은 15초마다 4번 울리면 과하다는 도그푸딩 피드백으로 `muteStepChime`
플래그를 콘텐츠에 얹어 전환음을 생략했다(카드 열림음·종료음은 그대로 남는다).

## 검증

- `tsc --noEmit` / `eslint`(변경 파일) / `cargo check` / vitest **208개** 전부 통과
- **실 도그푸딩 DB 대상 `--debug-cmd` 자동 검증 + 화면 캡처** (두 라운드, 아래 시행착오 참고)

### 시행착오 1 — 실행 중이던 설치본을 끄고 dev 로 전환

single-instance 때문에 검증 전 실행 중이던 0.4.2 설치본(PID 23232)을 사용자
승인 받아 종료했다(재실행은 하지 않음, 세션 종료 시점 사용자에게 알림).

### 시행착오 2 — 중첩 셸이 `--debug-cmd` 의 콤마를 공백으로 깨뜨렸다

dev 인스턴스를 백그라운드로 띄우려고 `powershell.exe -Command "<pnpm 명령 전체>"`
로 감쌌더니, 그 안에 담긴 `--debug-cmd "wait:3000,action-toggle:...,quit"` 문자열의
**콤마가 전부 공백으로 바뀐 채** 최종 실행 파일에 도달했다(`wait:3000,action-toggle`
→ `wait:3000 action-toggle`). 결과적으로 Rust 쪽 `script.split(',')` 이 전체를
한 덩어리로 보고, 콜론 파싱도 깨져 스크립트가 사실상 무의미하게 실행됐다.
`Start-Process -FilePath powershell.exe -ArgumentList @('-Command', $inner)` 를
`Start-Job -ScriptBlock { param($debugScript) ... } -ArgumentList $debugScript` 로
바꿔 해결 — `Start-Job` 은 인자를 **타입 있는 파라미터**로 전달해 문자열을 다시
토큰화하지 않는다. 상세는 `docs/troubleshooting/powershell-nested-command-comma-corruption.md`

### 시행착오 3 — "카드가 뜨자마자 닫힌다"는 버그처럼 보였지만 실제 설정이었다

`action-toggle` 로 C1 만 남기고 카운트다운까지 갔더니 카드가 뜨자마자 즉시
닫혔다. 버그로 의심해 `db-dump`/`behaviors-dump` 로 조사했더니, **실제(도그푸딩)
DB 의 스트레칭 행위 시간이 이미 0초로 설정돼 있었다**(간격도 기본 50분이 아니라
30분으로 바뀌어 있었다 — 전부 사용자가 직접 바꾼 값). `duration_sec > 0` 일 때만
카운트다운으로 들어가는 건 D2.7 부터 있던 기존 규칙이라 코드 문제가 아니었다.
`dev-and-installed-share-db.md` 가 이미 남긴 교훈("낯선 값 = 버그로 단정하지
말 것")과 같은 패턴을 이번에도 그대로 밟았다.

### 실 데이터 오염 → 정확한 복구 (두 라운드 모두)

두 라운드 모두 `start-session`/`done`/`end-session` 이 섞인 검증이라 실
`work_sessions`/`completion_logs` 에 테스트 행이 생겼다. `sqlite3.exe` 가 한글
사용자 경로를 못 여는 기존 함정(`docs/troubleshooting/sqlite3-cli-non-ascii-path.md`)
은 이번엔 **DB 폴더로 `cd` 한 뒤 상대 경로 파일명만 넘기는 방법**으로 더 가볍게
우회했다(문서에 보강함). 매번 `started_at`/`session_id` 로 정확히 특정해 지웠고
(세션 17→16, 로그 141→140 두 번 확인), `action-toggle` 로 덮어쓴 실
`action_prefs`(8종 켬/끔)도 8개 전부 켬으로 복구했다(원래 상태 추정 근거:
첫 토글 직후 로그에 나머지 7개가 이미 "켬"으로 찍혀 있었다 — 100% 확신은
아니라고 사용자에게 명시). 두 번째 라운드에서는 세션을 만들기 전에 **SQL 로
직접 `duration_sec=60`, C1 만 `enabled=1`** 로 미리 세팅해 `action-toggle`
연쇄 이벤트를 아예 안 쓰는 방식으로 바꿔, 비동기 순서 문제의 여지 자체를 없앴다.
스트레칭 로테이션 포인터(`action_index`)만 원래 값을 기록해 두지 않아 복구하지
못했다 — C1(3번)로 남았고, 통계엔 영향 없어 그대로 두기로 확인받았다.

### 캡처로 실제 화면 확인

`EnumWindows`+면적 최댓값(도구 세션 내 인라인 PowerShell, D2.8 때 정립한 방식)
으로 오버레이 창을 2초 간격 폴링하며 캡처. C1 카운트다운 60초 동안 4단계가
15초마다 정확히 전환되고(라벨·진행바·남은시간 전부), stdout 에 `sound step`
로그가 한 번도 안 찍혀(=전환음 생략 확인) 코드와 화면이 일치함을 확인했다.
