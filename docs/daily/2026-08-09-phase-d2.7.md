# 2026-08-09 — Phase D2.7: 행위 지속 시간 + 알림음 + 발화 큐

D2.6 까지 카드는 "떠서 문구를 보여주고 사라지는 것"이었다. D2.7 은 카드를 **행동이 끝날
때까지 함께 있는 것**으로 바꾼다. 세 가지가 한 덩어리다:

1. 행동마다 **행위 시간**(`durationSec`)이 생겼다 — 물마시기는 0초, 스트레칭은 60초
2. 그래서 **소리**가 필요해졌다. 눈을 감고 있으면 화면을 볼 수 없다 (시작 ①, 끝 ②)
3. 카드가 오래 머무니 그 사이 다음 알림이 도래한다 → **발화 큐** (`docs/decisions/0009`)

## 1. 행위 시간 (마이그레이션 v4)

`Behavior.countdownMs?` 를 없애고 `durationSec: number` 를 넣었다. optional 이 아닌 게 핵심 —
**0 은 "값 없음"이 아니라 「즉시 행동」이라는 뜻**이다. 물 한 잔은 마시는 데 시간이 걸리는
행동이 아니고, [완료]를 누르면 그걸로 끝나야 한다.

D2 의 「1분만 같이 세어볼까요?」 제안 단계(`phase: 'offer'`)는 없앴다. 행위 시간이 행동의
속성이 된 이상, 셀지 말지는 **매번 물을 일이 아니라 설정에서 정할 일**이다. 이제 [완료]는
0초면 바로 닫고, 0초 초과면 그 자리에서 카운트다운으로 바뀐다.

마이그레이션 v4 는 세 줄이다.

```sql
ALTER TABLE behaviors ADD COLUMN duration_sec INTEGER NOT NULL DEFAULT 0;
UPDATE behaviors SET duration_sec = countdown_ms / 1000 WHERE countdown_ms > 0;
UPDATE behaviors SET duration_sec = 60
 WHERE id = 'eyes' AND is_builtin = 1 AND duration_sec = 0;
```

- 둘째 줄: 기존 값을 **흡수**한다. 사용자가 고쳐 둔 카운트다운이 있으면 그게 살아난다
- 셋째 줄: 눈휴식은 「눈감고 1분」이 행동 정의 자체인데(CLAUDE.md 시드) D2 에는 카운트다운이
  안 붙어 있어 흡수할 값이 없다. **내장 눈휴식에만, 아직 0 일 때만** 채운다
- `countdown_ms` 열은 **안 지웠다.** SQLite 의 `DROP COLUMN` 은 버전을 타고, 마이그레이션이
  실패하면 앱이 아예 안 켜진다. 값을 옮긴 뒤로는 아무도 읽지 않는다(어댑터의 SELECT/INSERT
  목록에서 빠졌다)

`routineParse` 는 손대지 않았다 — AI 유래 행동은 `durationSec=0` 으로 들어온다. `[HOURSTEP]`
형식에 칸을 하나 더 요구하면 파싱 실패율이 올라가고, 그 대가로 얻는 게 "AI 가 추측한 초"다.
필요해지면 그때 형식을 늘린다.

## 2. 알림음 (`src/windows/sound.ts`)

WebAudio 합성. 음원 파일을 번들하지 않는다 — 짧은 신호음 두 개는 코드 스무 줄이다.

- ① `start` — D5→A5 두 음, 올라가는 느낌. **카드가 뜰 때마다 무조건**
- ② `end` — D6 한 음, 짧고 높게. 카운트다운이 끝날 때만

둘을 귀로 구분할 수 있어야 한다. 눈을 감고 스트레칭하는 사람에게 ①과 ②는 정반대 지시다.

**무음인 자리**: 스누즈·건너뛰기·큐 대기 진입. 사용자가 이미 카드를 보고 있는 상황이라
소리는 정보가 아니라 방해다. 세션 종료 요약 카드도 무음이다 — 사용자가 방금 [작업 종료]를
눌러서 뜬 것이고 알림이 아니라 보고서다.

재생 주체는 **오버레이 창**이다(메인 창은 트레이로 숨어 있을 수 있다). 설정 창은
[🔊 미리듣기]에만 같은 모듈을 쓴다 — 볼륨 슬라이더는 들어보지 않으면 맞출 수 없다.

막힌 데가 하나 있었다. 웹뷰는 **사용자 조작 전까지 오디오를 재운다**(Chromium 자동재생 정책).
오버레이 창은 `WS_EX_NOACTIVATE` 라 포커스를 받지 않으니 그 조작이 영영 안 올 수도 있다.
`tauri.conf.json` 의 창 설정에 `additionalBrowserArgs` 로
`--autoplay-policy=no-user-gesture-required` 를 줬다. 주의 두 가지:

- **세 창에 같은 문자열을 줘야 한다.** WebView2 환경은 창끼리 공유되므로 창마다 다른 인자를
  주면 두 번째 창 생성이 실패할 수 있다
- 이 필드는 Tauri 기본값(`--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection`)을
  **덮어쓴다**. 그래서 기본 인자도 함께 적었다

`playCue()` 는 **예외를 던지지 않는다.** 소리가 안 나는 건 알림이 안 뜨는 것보다 훨씬 가벼운
실패인데, 던지면 카드 표시 경로가 통째로 멈춘다. 대신 결과를 한 줄 문자열로 돌려주고
그걸 `log_debug` 로 남긴다 — 자동 검증이 stdout 에서 그 줄을 찾는다.

설정은 전역 하나(`soundEnabled` + `soundVolume` 0~100 정수). 행동마다 소리를 다르게 두면
설정만 늘고 얻는 게 없다. 볼륨을 백분율 정수로 저장하는 이유는 부동소수를 JSON·DB 에
왕복시키지 않기 위해서다.

## 3. 발화 큐 (`src/core/overlayQueue.ts`)

근거는 `docs/decisions/0009`. 요약: **병합하지 않고 직렬화한다.**

지금까지는 카드가 떠 있으면 tick 이 그냥 지나갔다 — 즉 **새로 도래한 알림이 조용히
사라졌다.** `firedRef` 에 소진 표시까지 되어 다시 오지도 않는다. 물마시기를 30분마다 켜 뒀는데
스트레칭 카운트다운과 겹칠 때마다 한 건씩 증발하면 사용자는 이유를 알 수 없다.

큐 규칙:

- 카드 표시 중(카운트다운 포함) 도래 → 적재, **즉시 표시 금지**, **무음**
- 카드 종료(done/snoozed/skipped/카운트다운 끝) → 하나 꺼내 이어서 표시 (① 울림)
- 원래 `dueAt` 유지. 꺼낼 때 `STALE_MS` 를 다시 적용하지 **않는다** — 밀린 이유가 앞 카드였다면
  그건 사용자가 성실히 쉰 결과지 앱이 절전으로 자고 있던 게 아니다
- 상한 5건, 넘으면 오래된 것부터 드롭. **`skipped` 로 기록하지 않는다** (사용자가 건너뛴 게
  아니라 앱이 못 보여준 것 — 실천율을 사용자 탓으로 왜곡하면 안 된다). 로그에는 남긴다
- **세션 종료 시 전체 폐기**
- 스누즈는 큐와 무관. 기존 스케줄러 경로 그대로

이어 띄울 때 창을 숨겼다 다시 띄우지 않는다(한 프레임 깜빡인다). 슬라이드 아웃이 끝난 자리에서
다음 카드가 다시 슬라이드 인 한다.

큐 판단은 순수 함수로 뺐다(`enqueueOccurrence` / `dequeueOccurrence` / `summarizeQueue`).
오버레이 컴포넌트에 남은 건 `queueRef` 하나다.

## 4. 설정 UI

`IntervalInput` 을 `NumberInput` 으로 일반화했다(min/max/clamp 를 인자로). 행위 시간 칸이
간격 칸과 다르게 굴면 그게 더 놀랍기 때문 — D2.6 후속에서 간격 칸에 생긴 규칙(입력 중에는
문자열, blur 에서 경계 복구)을 그대로 물려받는다. `RoutineFinder` 의 미리보기 줄도 같은 칸을 쓴다.

행위 시간 입력은 문구 칸 아래 줄에 뒀다. 첫 줄은 이미 꽉 차 있다(체크박스·이모지·이름·태그·
간격·순서·삭제). 값 옆에 안내를 붙였다 — 「0초」가 무슨 뜻인지는 숫자만 봐서는 모른다.

- `durationSec === 0` → "완료를 누르면 바로 끝나요"
- `> 0` → "완료를 누르면 60초를 같이 세어드려요"

볼륨 슬라이더는 **드래그 중에 저장하지 않는다.** 화면만 먼저 움직이고 손을 뗄 때
(`onPointerUp`/`onKeyUp`/`onBlur`) 한 번 저장한다. 안 그러면 드래그 한 번에 DB 쓰기와
방송이 수십 번 나간다.

## 5. 자동 검증

새 `--debug-cmd`:

- `set-duration:<id>=<초>` — 카운트다운 분기를 60초 기다리지 않고 검증
- `set-sound:<on|off|0-100>` — 설정 창과 같은 저장·방송 경로
- `queue-dump` — 큐는 화면에 안 보인다. 이게 유일한 창구다

로그로 나가는 것: `sound start …` / `sound end …` / `queue push … (dropped=…)` /
`queue pop …` / `queue clear n=…`.

vitest **128개** (+ overlayQueue 11 / behaviors·settings 보강). 큐 테스트가 덮는 것:
빈 큐 pop, FIFO, 중복 occurrence 무시, 상한 초과 시 오래된 것 드롭, 상한 0, 원본 불변.

### 검증 결과 (2026-08-09, `--debug-cmd` 자동 검증 — stdout 파싱)

**① 사슬 전체** (`behaviors-dump → behavior-add ×2 → set-duration → start-session → tick →
done → tick → queue-dump → 카운트다운 종료 → queue-dump → done → end-session → 정리`):

```
[debug] behaviors n=3 0:stretch(🧘스트레칭,30m,60s,on,builtin) 1:eyes(👀눈휴식,30m,60s,on,builtin) 2:water(💧물마시기,30m,0s,on,builtin)
[debug] sound start volume=60 state=running     ← ① 카드 표시음
[debug-cmd] dump overlay.visible=true
[debug] queue n=0
[overlay] action = done                          ← 카운트다운 시작 (카드 유지)
[debug] queue push q2@1786259994809 n=1          ← 카운트다운 중 도래 → 적재, 무음
[debug] queue n=1 q2@1786259994809
[debug] sound end volume=60 state=running        ← ② 카운트다운 종료음
[debug] queue pop q2@1786259994809 n=0           ← 다음 카드 자동 표시
[debug] sound start volume=60 state=running      ← ① 다시
```

- **마이그레이션 v3→v4 가 기존 데이터를 보존했다.** 첫 줄이 그 증거다 — 사용자가 바꿔 둔
  간격(30m ×3)이 그대로고, `duration_sec` 은 스트레칭 60s(= `countdown_ms` 흡수) /
  눈휴식 60s(내장 대상 UPDATE) / 물마시기 0s 로 채워졌다
- `state=running` — 웹뷰 오디오가 잠들지 않았다. 자동재생 인자가 먹었다는 1차 증거
  (실제 소리가 스피커로 나갔는지는 귀로 확인해야 한다)
- 세션 종료 요약 카드 뒤에 `sound` 줄이 없다 = 요약은 무음 ✅

**② 무음 경로 + 세션 종료 시 큐 폐기** (`set-sound:off` / 큐에 1건 있는 채로 `end-session`):

```
[debug] settings sound=off volume=60
[debug] sound start skipped=off                  ← 꺼져 있으면 재생하지 않는다
[debug] queue push z2@1786260087884 n=1
[debug] queue n=1 z2@1786260087884
[debug] queue clear n=1                          ← 세션 종료 → 통째로 폐기
[debug] queue n=0
```

**회귀**: 두 스크립트 모두 끝에서 테스트 행동을 지우고 `behaviors-dump` 를 다시 찍었다.
사용자 행동 3종이 처음과 **완전히 같은 줄**로 돌아왔다. `db-dump` 의 `open=0` 으로 미종료
세션도 남지 않았음을 확인했다.

> 오늘 통계에 섞였다(`🧪q1`/`🧪q2` 이름 스냅샷으로 남는다). dev 와 설치본이 같은 DB 를 쓰기

## 남은 것 (귀·눈으로)

- **소리를 실제로 들어봐야 한다.** ①과 ②가 구분되는지, 볼륨 기본 60이 적당한지,
  자동재생 정책 인자가 실기기에서 통하는지 (`state=running` 이 로그에 찍히는지로 1차 확인)
- 카운트다운 숫자(30px)가 카드에서 읽히는지, 이어 뜨는 카드가 자연스러운지
- 설정 창 행동 행이 한 줄 더 늘었다 — 20개까지 늘어놨을 때 여전히 볼 만한지
