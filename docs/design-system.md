# 디자인 시스템 (D2.8)

> **규칙 한 줄: 새 색·간격·글자 크기가 필요하면 먼저 `src/styles/tokens.css` 에 토큰으로
> 정의하고, 그 이름을 참조한다.** 창별 CSS 에 리터럴을 적지 않는다.
> `src/styles/tokens.test.ts` 가 잔존 여부를 자동으로 잡는다 — 사람 리뷰에 맡기지 않는다.

## 왜 있는가

D2.5 에서 색을 CSS 변수로 옮겼지만 **규격 문서가 없어서** 창마다 값이 갈렸다.
같은 성격의 버튼이 `.ghost` / `.chip` / `.btn` / `.session__toggle` 네 벌로 나뉘어 있었고,
라이트 모드를 붙일 때 네 군데를 따로 손봐야 했다. 반경은 6·7·8·9·10·12·14·18px 여덟 종,
글자 크기는 11~34px 열두 종이 돌아다녔다.

D2.8 은 기능을 하나도 늘리지 않는다. 값의 출처를 한 곳으로 모으고 화면을 거기에 맞췄다.

## 파일

| 파일 | 역할 |
| --- | --- |
| `src/styles/tokens.css` | 토큰 **정의**. 색 리터럴을 쓸 수 있는 유일한 파일 |
| `src/styles/components.css` | 공통 컴포넌트 스타일. `src/components/*.tsx` 와 1:1 |
| `src/styles/base.css` | 리셋 + 위 둘 import + 포커스 링. 창별 `main.tsx` 는 이것만 읽는다 |
| `src/windows/<창>/*.css` | 그 창에서만 쓰는 것. 토큰만 참조한다 |

## 1. 토큰

### 색

두 벌(`:root` = 다크 기본, `:root[data-theme='light']`)이 **같은 이름 집합**을 갖는다.
한쪽에만 있는 토큰이 생기면 테스트가 잡는다.

| 토큰 | 쓰임 |
| --- | --- |
| `--bg` | 창 배경 |
| `--bg-elevated` | 창 배경 위로 올라온 면 (패널·토스트) |
| `--bg-sunken` | 눌러 앉은 면 (목록 행, 보조 버튼). **반투명** |
| `--bg-hover` | hover 워시. **반투명** |
| `--text` / `--text-muted` / `--text-subtle` | 본문 / 보조 / 안내 |
| `--border` | 보통 선 (패널 테두리, 목록 구분선) |
| `--border-strong` | 경계가 분명해야 하는 선 (입력칸, 보조 버튼) |
| `--accent` | **채우는** 강조색 (주 버튼, 체크박스, 슬라이더) |
| `--accent-hover` | 그 hover |
| `--accent-fg` | `--accent` 위에 얹는 글자 |
| `--accent-tint` / `--accent-line` | 강조 배경 틴트 / 그 테두리 (배지·태그·다음 알림 줄) |
| `--accent-text` | 본문 배경 위에 쓰는 강조색 **글자** |
| `--danger` / `--success` / `--warn` | 상태색 |
| `--field-bg` | 입력칸 배경 (테두리는 `--border-strong`) |
| `--focus` | 키보드 포커스 링 |
| `--overlay-bg` / `--overlay-border` / `--overlay-edge-top` / `--overlay-edge-bottom` | 오버레이 카드 전용 |
| `--shadow-1` / `--shadow-2` | 그림자. **오버레이 창에서는 금지** (아래 참조) |

`--bg-sunken` 과 `--bg-hover` 가 불투명 색이 아니라 반투명인 이유: 같은 컴포넌트가
창 배경 위에도, 오버레이 카드(자체 배경을 가진 면) 위에도 서야 하기 때문이다.
불투명 색을 쓰면 카드 위에서 사각형 얼룩이 된다.

`--accent` 가 라이트/다크 같은 값인 이유: `--accent-fg`(흰색)가 4.5:1 을 넘는 파랑은
폭이 좁고, 두 테마가 서로 다른 파랑을 쓸 이유가 없다. 어두운 배경 위에 **글자로** 쓰는
강조색이 필요하면 `--accent-text`(다크에서 밝은 파랑)가 따로 있다.

### 대비 (WCAG AA 본문 4.5:1)

D2.8 에서 실측하고 고친 값. 계산은 WCAG 2.x 상대휘도 공식.

| 조합 | 이전 | 지금 |
| --- | --- | --- |
| 다크 `--text-subtle` on `--bg-elevated` | #6f768a → **3.68** ✗ | #868ea2 → **5.08** ✓ |
| 라이트 `--text-subtle` on `--bg` | #838b9d → **3.10** ✗ | #636b7e → **4.85** ✓ |
| 흰 글자 on 주 버튼 | 그러데이션 상단 #5b93ff → **2.9** ✗ | #2f6fe0 → **4.70** ✓ |
| 흰 글자 on 주 버튼 hover | — | #2559c2 → **6.39** ✓ |

주 버튼의 세로 그러데이션(`--accent-grad`)을 없앤 것이 이 표의 세 번째 줄이다.
`--accent-hover` 라는 토큰은 그러데이션과 같이 갈 수 없고, 두 정지점 중 밝은 쪽이
흰 글자와 3:1 도 못 넘겼다.

나머지(`--text`, `--text-muted`, `--accent-text`, `--danger`)는 두 테마 모두
원래 4.5:1 을 넘겼고 값을 바꾸지 않았다.

### 간격 — 4px 배수 고정

`--sp-1:4` `--sp-2:8` `--sp-3:12` `--sp-4:16` `--sp-6:24` `--sp-8:32`

**padding / margin / gap 은 여기서만 고른다.** 20px 단(`--sp-5`)은 일부러 두지 않았다 —
16 과 24 사이가 필요하다고 느끼면 대개 레이아웃 쪽 문제다.

요소의 **크기**(폭·높이·max-width)는 이 눈금 밖이다. 카드 폭 540px, 이모지 칸 48px,
숫자칸 64px 같은 것은 그 자리에서 정한다. 테스트도 여백만 본다.

### 반경 / 그림자

`--r-sm:6` `--r-md:10` `--r-lg:14` `--r-full:999`

`--shadow-1` / `--shadow-2`. **오버레이 창에서는 쓰지 않는다** — 아래 「오버레이 제약」.

### 타이포 — 글자는 4단만

`--fs-xs:12` `--fs-sm:13` `--fs-md:15` `--fs-lg:20`
`--fw-normal:400` `--fw-medium:500` `--fw-bold:600`
`--lh-base:1.5` (기본) / `--lh-tight:1.2` (숫자·제목)

숫자를 표시하는 자리에는 `font-variant-numeric: tabular-nums` 를 같이 준다.
매초 갱신되는 값에서 자릿수가 바뀔 때 폭이 흔들리지 않아야 한다.

**스케일 밖 예외 두 개.** 글자가 아니라서 4단에 넣지 않았고, 쓰는 자리를 여기 못 박는다.
새로 쓰려면 이 문서를 먼저 고칠 것.

| 토큰 | 값 | 쓰는 자리 (전부) |
| --- | --- | --- |
| `--fs-display` | 30px | 메인 창 경과시간 / 오버레이 카운트다운 |
| `--fs-icon` | 24px | 오버레이 카드의 이모지 글리프 |

카운트다운은 눈을 감고 있다가 뜨거나 스트레칭 자세에서 곁눈질로 읽는 숫자라
본문 스케일로 줄일 수 없다. 경과시간도 같은 크기로 맞춰 두 화면의 「큰 숫자」를 통일했다.

### 모션

`--dur-fast:120ms` `--dur-base:200ms` `--ease: cubic-bezier(.2,.8,.2,1)`

**예외**: 오버레이 카드의 슬라이드 인/아웃(320ms / 220ms)은 토큰을 쓰지 않는다.
`OverlayWindow.tsx` 의 `SLIDE_OUT_MS` 와 짝이 맞아야 하는 값이라, 토큰을 건드리면
JS 쪽이 조용히 어긋난다. 그 자리에 주석으로 이유를 남겨 두었다.

## 2. 컴포넌트 (`src/components/`)

| 컴포넌트 | 규격 |
| --- | --- |
| `Button` | `variant` = primary \| secondary \| ghost \| danger, `size` = sm(28px) \| md(34px), `icon`(정사각형). **전 창에서 이것만 쓴다** |
| `NumberField` | 간격(분)·행위 시간(초)·리마인더(분) 공통. 입력 중 문자열 · blur 에서 clamp |
| `Checkbox` | 라벨을 주면 라벨까지 클릭 영역 |
| `Card` | `variant` = panel(패널) \| row(목록 한 줄) |
| `Section` | 제목 + 본문 |
| `EmptyState` | 보여줄 게 없을 때의 한 줄 |

### Button 고르는 법

- **primary** — 그 화면의 주된 행동, 또는 되돌릴 수 없는 것 (작업 시작 / [완료] / 삽입)
- **secondary** — 나란히 서는 보통 행동 (설정 열기 / 복사 / 미리듣기 / 행동 추가)
- **ghost** — 물러나 있는 행동 (건너뛰기 / 나중에 / 닫기 / ↑↓)
- **danger** — 지우는 행동. 평소엔 조용하고 hover 에서만 붉어진다

비활성은 네 변형 모두 `opacity: .45` + `cursor: default` 하나로만 구분한다.
변형마다 색을 따로 잡으면 넷이 어긋난다.

### Toggle 을 만들지 않은 이유

이 앱의 on/off 는 전부 체크박스다. 스위치 UI 를 쓰는 자리가 하나도 없는데
컴포넌트만 만들어 두면 그건 죽은 코드다. 필요해지는 날 만든다.

## 3. 오버레이 제약

오버레이 창은 **카드 실크기로 리사이즈된다** (`docs/decisions/0005`). 여기서 나오는 규칙:

1. **그림자 금지.** 창 밖으로 번지는 부분이 잘린다. 입체감은 테두리 + 안쪽 그림자
   (`--overlay-edge-top` / `--overlay-edge-bottom`)로만 낸다.
   `tokens.test.ts` 가 `overlay.css` 에 `--shadow-*` 가 들어오면 실패시킨다
2. **카드 바깥 여백 금지.** 여백만큼이 「클릭이 막히는 투명한 죽은 영역」이 된다
3. **자체 대비를 스스로 확보한다.** 임의의 배경(에디터·브라우저·게임) 위에 뜨므로
   창 배경색에 기댈 수 없다. 그래서 `--overlay-*` 토큰이 따로 있고,
   라이트 쪽 테두리를 다크보다 진하게 잡아 두었다
4. **포커스 링은 예외.** `WS_EX_NOACTIVATE` 라 카드가 키보드 포커스를 받지 못한다
   (「알려진 한계 5」). 규칙을 창마다 갈라 두지는 않았다 — 포커스가 안 오면 링도 안 뜬다

## 4. 자동 검증

`pnpm test` 가 다음을 강제한다 (`src/styles/tokens.test.ts`).

- `tokens.css` 가 라이트/다크 두 벌을 정의하고, **두 벌의 토큰 이름 집합이 같다**
- 나머지 CSS 5개 파일에 색 리터럴(`#…` / `rgb()` / `hsl()`)이 **0건**
- 그 파일들의 `padding` / `margin` / `gap` 값이 전부 `var(--sp-*)` · `0` · `%` · `calc(토큰)`
- `overlay.css` 에 `--shadow-*` 가 없다
- 검사 대상 파일 목록이 기대와 일치한다 (경로가 어긋나 0건을 검사하고 통과하는 사고 방지)

stylelint 를 들이지 않은 이유: 규칙 네 개 때문에 의존성과 설정 파일이 늘어난다.
지금 규칙은 정규식 몇 줄로 충분하고, 이미 돌고 있는 vitest 에 얹힌다.
