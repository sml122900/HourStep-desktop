# Phase D0 수동 검증 절차

> 목적: "상주 + 오버레이"가 **실제 Windows 데스크톱 환경에서 통하는지**를 사람 눈으로 확인한다.
> 제품 기능(세션/스케줄러/통계)은 D1~D2 범위이므로 여기서 검증하지 않는다.
>
> 권장 순서: **B → C → D → E → F → A** (A는 재부팅이 들어가서 마지막)

## 0. 준비

```powershell
pnpm tauri dev
```

로그 확인 위치

| 로그 | 어디서 보나 |
| --- | --- |
| `[tray] …`, `[overlay] …`, `[app] …`, `[spike] …` | `pnpm tauri dev` 를 띄운 터미널 (Rust stdout) |
| `[overlay] action = …` | 위 터미널 + 오버레이 창 devtools 콘솔 (우클릭 → 검사) |

### `--debug-cmd` 디버그 훅

CLAUDE.md 「검증 정책」에 따라, 트레이/버튼 클릭이 필요한 시나리오는 합성 입력 대신
**같은 핸들러를 직접 호출**해서 검증한다. 개발 빌드 전용(`#[cfg(debug_assertions)]`)이라
릴리스 번들에는 들어가지 않는다.

`--` 를 **세 번** 써야 앱까지 전달된다 (pnpm 이 하나, tauri 가 하나 먹는다):

```powershell
pnpm tauri dev -- -- -- --debug-cmd "wait:4000,dump,start-session,wait:1500,dump,quit"
```

| 명령 | 동작 |
| --- | --- |
| `wait:<ms>` | 대기 |
| `start-session` | 트레이 `▶ 작업 시작` 과 같은 핸들러 |
| `overlay-show` / `overlay-hide` | 오버레이 표시 / 숨김 |
| `overlay-action:done\|snoozed\|skipped` | 프론트엔드 `dismiss()` 를 그대로 태움 (버튼 클릭과 같은 경로) |
| `settings-open` / `main-show` / `main-hide` | 창 조작 |
| `dump` | 세 창의 표시 여부를 `[debug-cmd] dump <label>.visible=<bool>` 로 출력 |
| `quit` | 트레이 `종료` 와 같은 경로 (`app.exit(0)`) |
| `loop` | 맨 끝에 붙이면 전체 스크립트 무한 반복 |

**C 항목(전체화면)** 은 전체화면에서 트레이를 누를 수 없으므로 반복 모드를 쓴다:

```powershell
pnpm tauri dev -- -- -- --debug-cmd "wait:8000,overlay-show,wait:8000,overlay-hide,wait:12000,loop"
```

훅의 한계:
- **자기 프로세스 안에서만** 동작한다. 이미 떠 있는 다른 인스턴스에는 명령을 못 보낸다
  (그러려면 single-instance 플러그인 + argv 전달 필요 — D3 범위)
- **"실제 마우스 클릭이 `WS_EX_NOACTIVATE` 창에 전달되는가"는 증명할 수 없다.**
  그건 격리 환경(Windows Sandbox/VM) E2E 의 몫이다

> ⚠️ **중복 실행 방지가 아직 없다.** dev 인스턴스와 설치 버전을 동시에 켜면 트레이 아이콘이 두 개 생기고
> 어느 쪽 로그인지 헷갈린다. 항상 한 쪽만 켤 것.

## B. 브라우저 위 표시 + 포커스 + Alt+Tab (5분)

목적: 카드가 다른 앱 위에 뜨되, 작업을 방해(포커스 강탈)하지 않는지.

1. 브라우저를 최대화하고 검색창 등 입력란을 클릭해 커서를 둔다
2. 아무 글자나 타이핑해서 입력이 되는 상태임을 확인
3. 트레이 우클릭 → **테스트 알림**

- [x] **B-1** 카드가 브라우저 위(화면 중앙 상단)에 보인다
- [x] **B-2** 카드가 뜬 직후, 입력란을 다시 클릭하지 않고 **바로 타이핑을 계속했을 때 글자가 그대로 입력된다**
  ← 포커스 미탈취. **이 테스트의 핵심**
- [x] **B-3** 카드가 떠 있는 상태에서 Alt+Tab → 전환 목록에 오버레이 창이 **없다**
  (Alt+Tab 누르는 순간 카드가 사라질 수 있으니 목록에 있는지만 빠르게 확인)

4. 다시 테스트 알림 → 카드의 **[✅ 완료]** 클릭

- [x] **B-4** 카드가 슬라이드 아웃으로 사라지고, 터미널에 `[overlay] action = done` + `[overlay] hide` 가 찍힌다
- [x] **B-5** 카드가 사라진 뒤, **카드가 있던 화면 상단 중앙 영역의 브라우저(탭 바 등)를 클릭 → 정상 동작한다**
  ← "유령 사각형" 버그(D0에서 잡음)의 **회귀 테스트**. `docs/decisions/0001` 참고

5. `[⏰ 3분 뒤]`, `[건너뛰기]` 도 눌러 로그가 `snoozed` / `skipped` 로 구분되는지 확인

- [x] **B-2'** 실제 마우스로 버튼을 클릭한 **직후**에도 포커스가 뒤 창에 유지된다 (2026-08-07 사용자 실측)
- [x] **B-4b** 실제 마우스 클릭이 `WS_EX_NOACTIVATE` 창에 전달된다 — 3버튼 모두 (2026-08-07 사용자 실측)

> 카드가 **떠 있는 동안** 카드 주변 투명 영역의 클릭이 막히는 것은 알려진 한계라 실패로 치지 않는다.
> B-5는 카드가 **사라진 뒤**를 보는 것이므로 별개다.

## C. 전체화면 위 표시 ⚠️ 가장 중요 (5~10분)

목적: **어떤 전체화면 모드에서 카드가 뜨고 안 뜨는지 목록을 만든다** (D3 설계 입력).
합격/불합격이 아니라 **기록이 목적**이다.

자동 오버레이 모드로 재시작한 뒤, 각 모드에 진입해 카드가 뜰 때까지(최대 20초) 기다린다.

- [x] **C-1** 유튜브 재생 → 플레이어 전체화면(F) → 카드가 영상 위에 뜬다
- [x] **C-2** 브라우저 자체 전체화면(F11) → 카드가 뜬다
- [x] **C-3** (있는 경우) 동영상 플레이어(팟플레이어 등) 전체화면 → 카드가 뜬다
- [x] **C-4** (있는 경우) 게임 — 테두리 없는 창(borderless) 모드 → 카드가 뜬다
- [x] **C-5** (있는 경우) 같은 게임 — 배타적 전체화면(exclusive) 모드 → 카드가 뜨는가?

> **C-5는 실패가 예상되는 지점이고, 실패해도 D0 실패가 아니다.**
> Windows는 배타적 전체화면 앱이 포그라운드일 때 topmost 창도 억제한다.
> 브라우저 전체화면은 borderless라 정상 동작하는 것이 정상.

### 실패 기록 (D3 "전체화면 감지 → 지연 표시" 설계에 그대로 들어감)

```
실패 앱/모드: 없음 (2026-08-07 실측)
  C-1 유튜브 플레이어 Fullscreen API : 뜸
  C-3 팟플레이어 전체화면            : 뜸
  C-4 게임 borderless                : 뜸
  C-5 게임 exclusive                 : 뜸  ← 예상과 다름
```

> ⚠️ **C-4/C-5 는 게임명이 기록되지 않았고, C-5 의 "배타적 여부"가 확증되지 않았다.**
> 요즘 게임은 옵션에 `전체화면` 이라고 써 있어도 DXGI flip model 로 내부적으로 borderless 인
> 경우가 많다. 그 경우 C-5 는 C-4 의 재측정에 불과하다. **D3 착수 전 게임명 + 모드 전환 시
> 해상도 깜빡임 유무를 확인해 이 칸을 보강할 것.**

## D. 듀얼 모니터 ⚠️ (5분 — 모니터 1대면 "해당 없음" 체크 후 스킵)

목적: 카드가 **항상 주 모니터** 중앙 상단에 정확히 뜨는지.

1. 마우스 커서를 **보조 모니터**에 둔 채 트레이 → 테스트 알림

- [ ] **D-1** 카드가 (커서 위치와 무관하게) **주 모니터** 중앙 상단에 뜬다 — 해당 없음

2. Windows 설정 → 시스템 → 디스플레이 → 보조 모니터 선택 → "여러 디스플레이" → "이 디스플레이를 주 모니터로 설정"
3. 트레이 → 테스트 알림

- [ ] **D-2** 카드가 새 주 모니터의 중앙 상단에 뜬다 — 해당 없음
- [ ] **D-3** 두 모니터 배율이 다르면(100%/125% 등) 위치가 어긋나거나 크기가 이상하지 않다
  (어긋나면 몇 % / 몇 % 조합인지 기록) — 해당 없음
- [x] **해당 없음** (모니터 1대) — `Screen.AllScreens` = 1개로 자동 확인

4. 테스트 후 주 모니터 원상복구

> 현재 정책은 "항상 주 모니터" (`src/core/overlayPosition.ts`).
> "커서가 있는 모니터" 또는 "활성 창이 있는 모니터"로 바꾸는 건 D3에서 결정한다.

## A. 재부팅 자동 상주 — 설치 버전으로 (10분, 재부팅 포함)

> ⚠️ 시작 전 dev 인스턴스를 완전히 종료 (트레이 **종료** + 터미널 Ctrl+C)

1. `src-tauri/target/release/bundle/nsis/HourStep_0.1.0_x64-setup.exe` 실행
2. 설치된 HourStep 실행 → 트레이 우클릭 → **설정** → 자동시작 켜기
3. 레지스트리 확인:
   ```powershell
   Get-Item "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" |
     Select-Object -ExpandProperty Property |
     ForEach-Object { "$_ = $((Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run').$_)" }
   ```

- [x] **A-1** HourStep 항목이 있고, 값에 설치 경로 exe + `--autostart` 인자가 보인다
  ```
  HourStep : "C:\Users\<user>\AppData\Local\HourStep\HourStep.exe" --autostart
  ```

4. 재부팅 → 로그인 후 1분 이내 확인

- [x] **A-2** 메인 창이 뜨지 않았다 (깜빡임도 없이)
- [x] **A-3** 트레이(오버플로 `^` 포함)에 HourStep 아이콘이 있다
- [x] **A-4** 트레이 → 테스트 알림 → 설치 버전에서도 카드가 정상 동작한다

5. 정리: 설치 버전을 트레이에서 종료한 뒤 dev로 복귀 (중복 실행 방지 전까지 항상 한 쪽만)

> 자동 실행 판별은 `--autostart` 인자 유무 (`src-tauri/src/lib.rs`). 수동 실행 시에는 메인 창이 떠야 정상이다.

> ⚠️ **1차 자동 검증의 일부는 지금은 금지된 방법으로 얻었다.**
> 당시 사용자 데스크톱 세션에 `SendInput` 합성 입력을 주입했고, 그 과정에서 클릭·키 입력이

> **합성 입력 주입을 금지**했다. 아래 표의 `방법` 열이 `SendInput` 인 항목은
> `--debug-cmd` 디버그 훅 또는 격리 환경(Windows Sandbox/VM)에서 **재검증 대상**이다.
> 상태 검사(`EnumWindows` / `GetWindowLongW` / `WindowFromPoint`)와 화면 캡처는 읽기 전용이라 유효하다.

### 추가로 확정된 사실

카드가 **떠 있는 동안** 오버레이 창 영역(640×240) 안의 6개 지점을 히트테스트한 결과,

> 타이틀(`Chrome Legacy Window`)만 보면 오독하기 쉬우니 `GetAncestor(h, GA_ROOT)` 로 확인할 것.

## 자동으로 이미 검증된 것 (참고)

| 항목 | 실측값 | 판정 |
| --- | --- | --- |

## 알려진 한계 (D0에서 의도적으로 남긴 것)

1. **오버레이 창의 투명 영역도 클릭을 가로챈다.** ← 히트테스트로 실측 확인됨
   카드가 떠 있는 동안 화면 상단 중앙 640×240 사각형 전체가 뒤 창의 클릭을 막는다.
   Win32 히트테스트는 CSS `pointer-events` 를 모르기 때문. 커서 위치를 추적해
   `setIgnoreCursorEvents` 를 토글하는 것이 정공법. **수정 Phase 미확정 (D1 or D3)**
2. ~~**배타적 전체화면 게임 위에는 뜨지 않을 수 있다.**~~ → **2026-08-07 실측에서는 떴다.**
   이 환경에서는 해당 없음. 단 C-5 의 게임명·모드 확증이 안 돼 있어 **완전히 지우지는 않는다** —
   D3 에서 게임 2~3종으로 재확인 후 정식 폐기 여부 결정
