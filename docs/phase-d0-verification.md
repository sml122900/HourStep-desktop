# Phase D0 수동 검증 절차

> 목적: "상주 + 오버레이"가 **실제 Windows 데스크톱 환경에서 통하는지**를 사람 눈으로 확인한다.
> 제품 기능(세션/스케줄러/통계)은 D1~D2 범위이므로 여기서 검증하지 않는다.
>
> 권장 순서: **B → C → D → E → F → A** (A는 재부팅이 들어가서 마지막)

## 0. 준비

```powershell
pnpm tauri dev
```

로그 확인 위치

| 로그 | 어디서 보나 |
| --- | --- |
| `[tray] …`, `[overlay] …`, `[app] …`, `[spike] …` | `pnpm tauri dev` 를 띄운 터미널 (Rust stdout) |
| `[overlay] action = …` | 위 터미널 + 오버레이 창 devtools 콘솔 (우클릭 → 검사) |

### 자동 오버레이 모드 (C 항목 필수)

전체화면에서는 트레이를 누를 수 없으므로 카드를 스스로 띄우는 모드를 쓴다.

```powershell
$env:HOURSTEP_SPIKE_AUTO_OVERLAY = "1"
pnpm tauri dev
```

- 앱 시작 **8초 뒤 첫 표시**, 이후 **8초 표시 / 12초 대기**를 반복 (주기 20초)
- 개발 빌드 전용 (`#[cfg(debug_assertions)]`). 릴리스 빌드에는 이 코드가 들어가지 않는다
- 끝나면 반드시 해제하고 재시작:
  ```powershell
  Remove-Item Env:HOURSTEP_SPIKE_AUTO_OVERLAY
  pnpm tauri dev
  ```

> ⚠️ **중복 실행 방지가 아직 없다.** dev 인스턴스와 설치 버전을 동시에 켜면 트레이 아이콘이 두 개 생기고
> 어느 쪽 로그인지 헷갈린다. 항상 한 쪽만 켤 것.

## B. 브라우저 위 표시 + 포커스 + Alt+Tab (5분)

목적: 카드가 다른 앱 위에 뜨되, 작업을 방해(포커스 강탈)하지 않는지.

1. 브라우저를 최대화하고 검색창 등 입력란을 클릭해 커서를 둔다
2. 아무 글자나 타이핑해서 입력이 되는 상태임을 확인
3. 트레이 우클릭 → **테스트 알림**

- [ ] **B-1** 카드가 브라우저 위(화면 중앙 상단)에 보인다
- [ ] **B-2** 카드가 뜬 직후, 입력란을 다시 클릭하지 않고 **바로 타이핑을 계속했을 때 글자가 그대로 입력된다**
  ← 포커스 미탈취. **이 테스트의 핵심**
- [ ] **B-3** 카드가 떠 있는 상태에서 Alt+Tab → 전환 목록에 오버레이 창이 **없다**
  (Alt+Tab 누르는 순간 카드가 사라질 수 있으니 목록에 있는지만 빠르게 확인)

4. 다시 테스트 알림 → 카드의 **[✅ 완료]** 클릭

- [ ] **B-4** 카드가 슬라이드 아웃으로 사라지고, 터미널에 `[overlay] action = done` + `[overlay] hide` 가 찍힌다
- [ ] **B-5** 카드가 사라진 뒤, **카드가 있던 화면 상단 중앙 영역의 브라우저(탭 바 등)를 클릭 → 정상 동작한다**
  ← "유령 사각형" 버그(D0에서 잡음)의 **회귀 테스트**. `docs/decisions/0001` 참고

5. `[⏰ 3분 뒤]`, `[건너뛰기]` 도 눌러 로그가 `snoozed` / `skipped` 로 구분되는지 확인

> 카드가 **떠 있는 동안** 카드 주변 투명 영역의 클릭이 막히는 것은 알려진 한계라 실패로 치지 않는다.
> B-5는 카드가 **사라진 뒤**를 보는 것이므로 별개다.

## C. 전체화면 위 표시 ⚠️ 가장 중요 (5~10분)

목적: **어떤 전체화면 모드에서 카드가 뜨고 안 뜨는지 목록을 만든다** (D3 설계 입력).
합격/불합격이 아니라 **기록이 목적**이다.

자동 오버레이 모드로 재시작한 뒤, 각 모드에 진입해 카드가 뜰 때까지(최대 20초) 기다린다.

- [ ] **C-1** 유튜브 재생 → 플레이어 전체화면(F) → 카드가 영상 위에 뜬다
- [ ] **C-2** 브라우저 자체 전체화면(F11) → 카드가 뜬다
- [ ] **C-3** (있는 경우) 동영상 플레이어(팟플레이어 등) 전체화면 → 카드가 뜬다
- [ ] **C-4** (있는 경우) 게임 — 테두리 없는 창(borderless) 모드 → 카드가 뜬다
- [ ] **C-5** (있는 경우) 같은 게임 — 배타적 전체화면(exclusive) 모드 → 카드가 뜨는가?

> **C-5는 실패가 예상되는 지점이고, 실패해도 D0 실패가 아니다.**
> Windows는 배타적 전체화면 앱이 포그라운드일 때 topmost 창도 억제한다.
> 브라우저 전체화면은 borderless라 정상 동작하는 것이 정상.

### 실패 기록 (D3 "전체화면 감지 → 지연 표시" 설계에 그대로 들어감)

```
실패 앱/모드:
  - 예) ○○게임 / 배타적 전체화면 / 카드 안 뜸, 소리도 없음
```

## D. 듀얼 모니터 ⚠️ (5분 — 모니터 1대면 "해당 없음" 체크 후 스킵)

목적: 카드가 **항상 주 모니터** 중앙 상단에 정확히 뜨는지.

1. 마우스 커서를 **보조 모니터**에 둔 채 트레이 → 테스트 알림

- [ ] **D-1** 카드가 (커서 위치와 무관하게) **주 모니터** 중앙 상단에 뜬다

2. Windows 설정 → 시스템 → 디스플레이 → 보조 모니터 선택 → "여러 디스플레이" → "이 디스플레이를 주 모니터로 설정"
3. 트레이 → 테스트 알림

- [ ] **D-2** 카드가 새 주 모니터의 중앙 상단에 뜬다
- [ ] **D-3** 두 모니터 배율이 다르면(100%/125% 등) 위치가 어긋나거나 크기가 이상하지 않다
  (어긋나면 몇 % / 몇 % 조합인지 기록)
- [ ] **해당 없음** (모니터 1대)

4. 테스트 후 주 모니터 원상복구

> 현재 정책은 "항상 주 모니터" (`src/core/overlayPosition.ts`).
> "커서가 있는 모니터" 또는 "활성 창이 있는 모니터"로 바꾸는 건 D3에서 결정한다.

## E. 메인 창 닫기 → 상주 유지 (2분)

1. 트레이 좌클릭 → 메인 창 열기
2. 메인 창의 **X** 클릭

- [ ] **E-1** 창은 사라지지만 트레이 아이콘은 남아 있다
- [ ] **E-2** 작업 관리자(Ctrl+Shift+Esc)에 `hourstep-desktop`(dev) / `HourStep`(설치본) 프로세스가 살아 있다

3. 트레이 → 테스트 알림

- [ ] **E-3** 카드가 여전히 정상 동작한다

4. 트레이 우클릭 → **종료**

- [ ] **E-4** 트레이 아이콘이 사라지고, 작업 관리자에서 프로세스도 사라진다 (터미널에 `[tray] 종료`)

## A. 재부팅 자동 상주 — 설치 버전으로 (10분, 재부팅 포함)

> ⚠️ 시작 전 dev 인스턴스를 완전히 종료 (트레이 **종료** + 터미널 Ctrl+C)

1. `src-tauri/target/release/bundle/nsis/HourStep_0.1.0_x64-setup.exe` 실행
2. 설치된 HourStep 실행 → 트레이 우클릭 → **설정** → 자동시작 켜기
3. 레지스트리 확인:
   ```powershell
   Get-Item "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" |
     Select-Object -ExpandProperty Property |
     ForEach-Object { "$_ = $((Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run').$_)" }
   ```

- [ ] **A-1** HourStep 항목이 있고, 값에 설치 경로 exe + `--autostart` 인자가 보인다

4. 재부팅 → 로그인 후 1분 이내 확인

- [ ] **A-2** 메인 창이 뜨지 않았다 (깜빡임도 없이)
- [ ] **A-3** 트레이(오버플로 `^` 포함)에 HourStep 아이콘이 있다
- [ ] **A-4** 트레이 → 테스트 알림 → 설치 버전에서도 카드가 정상 동작한다

5. 정리: 설치 버전을 트레이에서 종료한 뒤 dev로 복귀 (중복 실행 방지 전까지 항상 한 쪽만)

> 자동 실행 판별은 `--autostart` 인자 유무 (`src-tauri/src/lib.rs`). 수동 실행 시에는 메인 창이 떠야 정상이다.

## 결과 요약

자동 검증 1차 (2026-08-05, 1920×1080 단일 모니터 100%).
`SendInput` 합성 입력 + `Graphics.CopyFromScreen` 화면 캡처 + `WindowFromPoint` 히트테스트로 실행.

| 항목 | 결과 | 비고 |
| --- | --- | --- |
| **B-1** 카드가 브라우저 위에 표시 | ✅ | 스크린샷으로 확인 — Chrome/YouTube 위에 아이콘·문구·버튼 3개 정상 렌더링 |
| **B-2** 포커스 미탈취 | ✅ | 표시 순간 foreground 불변. **클릭 순간에도 불변** (`WS_EX_NOACTIVATE`) |
| **B-3** Alt+Tab 제외 | ✅ | `WS_EX_TOOLWINDOW` 설정 + `WS_EX_APPWINDOW` 해제 → 후보 판정 False (메모장은 True 로 로직 검증) |
| **B-4** 버튼 클릭 → 로그 → 사라짐 | ✅ | 합성 클릭으로 `[overlay] action = done` → `[overlay] hide` → `IsWindowVisible=False` |
| **B-5** 유령 사각형 회귀 | ✅ | 숨긴 뒤 같은 좌표 히트테스트가 실제 Chrome 을 반환 |
| **C-2** borderless 전체화면(F11) 위 | ✅ | 스크린샷으로 확인. 대상 창은 TOPMOST 아님 |
| **C-1** Fullscreen API(유튜브 F) 위 | ⏳ 미검증 | 자동화 셋업 실패(테스트 창이 포그라운드 상실). Chrome 기준 C-2 와 동일한 fullscreen 창 상태라 통과 가능성이 높지만 **실측 필요** |
| **C-3~C-5** 플레이어 / 게임 | ⏳ 미검증 | 실제 앱 필요. **C-5(배타적 전체화면)는 사람만 가능** |
| **D** 듀얼 모니터 | — 해당 없음 | `Screen.AllScreens` = 1개 (`\\.\DISPLAY1` 1920×1080, DPI 96) |
| **E-1/E-2** 창 닫기 → 상주 | ✅ | 메인 창에 `WM_CLOSE` → 창 숨김 + 프로세스 생존 |
| **E-3** 닫은 뒤 알림 동작 | ✅ | 메인 창이 숨겨진 상태에서 위 B 항목 전부 통과 |
| **E-4** 트레이 종료 | ⏳ 미검증 | 트레이 클릭 필요 |
| **F-1** 작업 시작 placeholder | ⏳ 미검증 | 트레이 클릭 필요 |
| **A** 재부팅 자동 상주 | ⏳ 미검증 | 재부팅 필요 |

### 추가로 확정된 사실

카드가 **떠 있는 동안** 오버레이 창 영역(640×240) 안의 6개 지점을 히트테스트한 결과,
카드 위·카드 배경·**투명 영역** 전부 root 창이 `HourStep Overlay` 로 잡혔다.
아래 "알려진 한계 1"이 추정이 아니라 **실측으로 확인된 사실**임을 뜻한다.

> 참고: 히트테스트가 반환하는 자식 창 클래스는 `Chrome_RenderWidgetHostHWND` 다.
> WebView2 가 Chromium 기반이라 그런 것이고 브라우저 Chrome 이 아니다. 자식 hwnd 의
> 타이틀(`Chrome Legacy Window`)만 보면 오독하기 쉬우니 `GetAncestor(h, GA_ROOT)` 로 확인할 것.

## 자동으로 이미 검증된 것 (참고)

`EnumWindows` + `GetWindowLongW(GWL_EXSTYLE)` + `GetForegroundWindow` 로 외부에서 실측한 값
(1920×1080 주 모니터, 100% 배율):

| 항목 | 실측값 | 판정 |
| --- | --- | --- |
| 표시 위치 | `rect = (640, 0) 640×240` | (1920−640)/2 = 640, y=0 → 중앙·최상단 ✅ |
| 확장 스타일 | `0x08000198` | `WS_EX_TOPMOST(0x8)` + `WS_EX_TOOLWINDOW(0x80)` + `WS_EX_NOACTIVATE(0x8000000)`, `WS_EX_APPWINDOW` 제거됨 ✅ |
| 포커스 | show 전후 foreground 창 PID 불변 (Unity 에디터가 포그라운드인 상태에서도) | 포커스 미탈취 ✅ |
| 숨김 | show 후 `IsWindowVisible = False` | 정상 숨김 ✅ |
| 창 닫기 | 메인 창에 `WM_CLOSE` → 창 숨김, 프로세스 생존 | E-1/E-2 사전 확인 ✅ |
| 메모리 | 약 32MB (dev 빌드) | Electron 대비 목표 달성 ✅ |

검사 스니펫은 `docs/daily/2026-08-05-phase-d0.md` 참고.
**B-2 / B-3 / C / D 는 자동 검증으로 대체할 수 없다** — 사람 눈이 필요하다.

## 알려진 한계 (D0에서 의도적으로 남긴 것)

1. **오버레이 창의 투명 영역도 클릭을 가로챈다.** ← 히트테스트로 실측 확인됨
   카드가 떠 있는 동안 화면 상단 중앙 640×240 사각형 전체가 뒤 창의 클릭을 막는다.
   Win32 히트테스트는 CSS `pointer-events` 를 모르기 때문. 커서 위치를 추적해
   `setIgnoreCursorEvents` 를 토글하는 것이 정공법. **수정 Phase 미확정 (D1 or D3)**
2. **배타적 전체화면 게임 위에는 뜨지 않을 수 있다.** (C-5, D3 범위)
3. **중복 실행 방지 없음.** `tauri-plugin-single-instance` 미적용 (D3)
4. **오버레이는 항상 주 모니터.** 커서/활성 창 기준 배치는 D3에서 결정
5. **키보드 조작 불가.** `WS_EX_NOACTIVATE` 때문에 카드가 키보드 포커스를 받지 않아 Tab/Enter로 버튼을 누를 수 없다.
   포커스 유지와 맞바꾼 것 — `src-tauri/src/overlay.rs` 의 `KEEP_FOCUS_ON_CLICK` 로 뒤집을 수 있다
