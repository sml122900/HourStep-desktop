# Phase D0 수동 검증 절차

> 목적: "상주 + 오버레이"가 **실제 Windows 데스크톱 환경에서 통하는지**를 사람 눈으로 확인한다.
> 제품 기능(세션/스케줄러/통계)은 D1~D2 범위이므로 여기서 검증하지 않는다.

## 0. 준비

```powershell
# 개발 모드로 실행 (Rust stdout 로그를 봐야 하므로 터미널을 띄워둔 채로)
pnpm tauri dev

# 설치본으로 검증할 때 (A 항목은 설치본으로 하는 게 정확)
# src-tauri/target/release/bundle/nsis/HourStep_0.1.0_x64-setup.exe 실행
```

로그 확인 위치

| 로그 | 어디서 보나 |
| --- | --- |
| `[tray] …`, `[overlay] …`, `[app] …` | `pnpm tauri dev` 를 띄운 터미널 (Rust stdout) |
| `[overlay] action = …` | 위 터미널 + 오버레이 창 devtools 콘솔 (우클릭 → 검사) |

---

## A. 재부팅 → 트레이 자동 상주

1. 트레이 아이콘 우클릭 → **설정** → `컴퓨터 켤 때 자동으로 시작` 체크
2. 체크가 실제로 등록됐는지 확인:
   ```powershell
   Get-Item "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" |
     Select-Object -ExpandProperty Property |
     ForEach-Object { "$_ = $((Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run').$_)" }
   ```
   HourStep 항목의 값에 실행 파일 경로와 `--autostart` 인자가 들어 있어야 한다.
3. Windows 재부팅
4. 확인할 것
   - [ ] 로그인 후 **창이 하나도 뜨지 않는다** (메인 창 자동 표시 금지)
   - [ ] 작업표시줄 트레이 영역에 HourStep 아이콘이 있다
   - [ ] 트레이 아이콘 **좌클릭** → 메인 창이 열린다
   - [ ] 트레이 아이콘 **우클릭** → `▶ 작업 시작` / `테스트 알림` / `설정` / `종료` 메뉴가 보인다
5. 되돌리기: 설정에서 체크 해제 후 위 레지스트리 조회로 항목이 사라졌는지 확인

> 자동 실행 판별은 `--autostart` 인자 유무로 한다 (`src-tauri/src/lib.rs`).
> 수동 실행 시에는 메인 창이 떠야 정상이다.

---

## B. 테스트 알림이 브라우저 창 위에 뜨는가

1. 브라우저(Chrome/Edge)를 **최대화**하고 포그라운드에 둔다
2. 트레이 우클릭 → **테스트 알림**
3. 확인할 것
   - [ ] 카드가 브라우저 **위에** 그려진다 (가려지지 않는다)
   - [ ] 화면 위쪽 밖에서 아래로 **슬라이드 인**된다
   - [ ] 카드 문구가 `🧘 일어나서 1분 스트레칭할 시간이에요` 이고 버튼 3개(`✅ 완료` / `⏰ 3분 뒤` / `건너뛰기`)가 보인다
   - [ ] **브라우저 타이틀바가 비활성 색으로 바뀌지 않는다** = 포커스를 뺏기지 않았다
   - [ ] 카드가 뜬 직후 브라우저에서 **바로 타이핑이 된다** (포커스 유지 확인의 실전 버전)
   - [ ] 작업표시줄에 HourStep 항목이 새로 생기지 않는다
   - [ ] **Alt+Tab** 을 눌렀을 때 오버레이가 후보에 없다
4. 버튼을 하나 누른다
   - [ ] 카드가 위로 **슬라이드 아웃**된 뒤 사라진다
   - [ ] 터미널에 `[overlay] action = done|snoozed|skipped` 와 `[overlay] hide` 가 찍힌다
   - [ ] 카드가 사라진 자리에서 **뒤 창이 정상적으로 클릭된다** (아래 "알려진 한계" 참고)
5. 세 버튼 각각에 대해 4를 반복 (`done` / `snoozed` / `skipped` 로그가 구분되어 찍히는지)

## C. 유튜브 전체화면 재생 위에 뜨는가

1. 유튜브 영상을 **전체화면(F)** 으로 재생
2. 트레이 메뉴는 전체화면에서 접근이 어려우므로, 전체화면 진입 **전에** 메인 창의 `테스트 알림 띄우기` 버튼을 쓰거나
   전체화면 상태에서 트레이를 띄우려면 마우스를 화면 하단으로 내려 작업표시줄을 부른 뒤 우클릭한다
3. 확인할 것
   - [ ] 카드가 전체화면 영상 **위에** 뜬다
   - [ ] 영상 재생이 끊기거나 전체화면이 해제되지 않는다
   - [ ] 버튼 클릭 후 카드가 사라지고 전체화면이 유지된다

> 참고: Windows는 **배타적 전체화면(exclusive fullscreen) 게임** 위에는 topmost 창도 억제한다.
> 브라우저 전체화면은 borderless 라서 정상 동작하는 것이 정상. 게임 대응은 D3(풀스크린 앱 감지) 범위다.
> 이 항목이 실패하면 **어떤 앱/모드에서 실패했는지**를 기록해 둘 것 — D3 설계 입력이 된다.

## D. 듀얼 모니터에서 주 모니터에 뜨는가

1. 모니터 2대 이상 연결. Windows 설정 → 시스템 → 디스플레이에서 어느 쪽이 **주 디스플레이**인지 확인
2. 마우스 커서와 활성 창을 **보조 모니터**에 둔 상태로 트레이 → 테스트 알림
3. 확인할 것
   - [ ] 카드가 **주 모니터** 가로 중앙·최상단에 뜬다 (커서가 있는 모니터가 아니라)
   - [ ] 카드가 두 모니터에 걸쳐 잘리지 않는다
4. 주 디스플레이를 다른 모니터로 바꾼 뒤 다시 테스트
   - [ ] 바뀐 주 모니터에 뜬다
5. 해상도/배율이 다른 모니터 조합(예: 1920 100% + 2560 150%)이 있으면 그 조합에서도 4를 반복
   - [ ] 배율이 다른 모니터에서도 카드가 중앙에 오고 크기가 이상하지 않다

> 현재 정책은 "**항상 주 모니터**"다 (`src/core/overlayPosition.ts`).
> "커서가 있는 모니터" 또는 "활성 창이 있는 모니터"로 바꾸는 건 D3 다중 모니터 항목에서 결정한다.

---

## E. 메인 창 닫기 → 트레이 생존 → 테스트 알림 여전히 동작

1. 메인 창을 연다 (트레이 좌클릭)
2. 창 오른쪽 위 **X** 로 닫는다
3. 확인할 것
   - [ ] 프로세스가 살아 있다:
     ```powershell
     Get-Process hourstep-desktop   # dev 빌드
     Get-Process HourStep           # 설치본
     ```
   - [ ] 트레이 아이콘이 그대로 있다
   - [ ] 작업표시줄에서 HourStep이 사라졌다
4. 트레이 우클릭 → **테스트 알림**
   - [ ] 카드가 정상적으로 뜨고 버튼이 동작한다
5. 트레이 우클릭 → **설정** → 창이 열린다 → **X** 로 닫는다 → 프로세스 생존 확인
6. 트레이 우클릭 → **종료**
   - [ ] 트레이 아이콘이 사라진다
   - [ ] `Get-Process` 결과가 비어 있다 (프로세스 완전 종료)
   - [ ] 터미널에 `[tray] 종료` 가 찍힌다

---

## F. 트레이 메뉴 placeholder 확인 (D1 범위 경계 확인용)

1. 트레이 우클릭 → **▶ 작업 시작**
   - [ ] 터미널에 `[tray] 작업 시작 (placeholder — D1에서 구현)` 만 찍힌다
   - [ ] 창이 뜨거나 타이머가 시작되는 등의 **다른 동작은 없어야 한다** (D0 범위 밖)

## 자동 스모크 (사람 클릭 없이 창 상태만 검사)

개발 빌드 한정. 트레이를 클릭하지 않고 오버레이를 4초 뒤 표시 → 8초 뒤 숨김.

```powershell
$env:HOURSTEP_SPIKE_AUTO_OVERLAY = "1"
pnpm tauri dev
```

D0 구현 시 이 경로로 실측한 값 (1920×1080 주 모니터, 100% 배율):

| 항목 | 실측값 | 판정 |
| --- | --- | --- |
| 표시 위치 | `rect = (640, 0) 640×240` | (1920−640)/2 = 640, y=0 → 중앙·최상단 ✅ |
| 확장 스타일 | `0x08000198` | `WS_EX_TOPMOST(0x8)` + `WS_EX_TOOLWINDOW(0x80)` + `WS_EX_NOACTIVATE(0x8000000)`, `WS_EX_APPWINDOW` 제거됨 ✅ |
| 포커스 | show 전후 foreground 창 PID 불변 | 포커스 미탈취 ✅ |
| 숨김 | show 8초 뒤 `IsWindowVisible = False` | 정상 숨김 ✅ |
| 메모리 | 약 32MB (dev 빌드) | Electron 대비 목표 달성 ✅ |

재현용 검사 스니펫은 `docs/daily/2026-08-05-phase-d0.md` 참고.

## 알려진 한계 (D0에서 의도적으로 남긴 것)

1. **오버레이 창의 투명 영역도 클릭을 가로챈다.**
   카드가 떠 있는 동안 화면 상단 중앙 640×240 사각형 전체가 뒤 창의 클릭을 막는다. 카드 바깥의 빈 공간도 마찬가지다.
   Win32 히트테스트는 CSS `pointer-events` 를 모르기 때문. 해결하려면 커서 위치를 추적해
   `setIgnoreCursorEvents` 를 토글해야 하며, **D3 폴리싱 범위**로 미룬다.
2. **배타적 전체화면 게임 위에는 뜨지 않을 수 있다.** (C 항목 참고, D3 범위)
3. **중복 실행 방지 없음.** 앱을 두 번 띄우면 트레이 아이콘이 두 개 생긴다.
   `tauri-plugin-single-instance` 적용은 D3 범위.
4. **오버레이는 항상 주 모니터.** 커서/활성 창 기준 배치는 D3에서 결정.
5. **키보드 조작 불가.** `WS_EX_NOACTIVATE` 때문에 카드가 키보드 포커스를 받지 않아 Tab/Enter로 버튼을 누를 수 없다.
   포커스 유지와 맞바꾼 것이며, 접근성이 필요해지면 전역 단축키로 푸는 편이 맞다.
   `src-tauri/src/overlay.rs` 의 `KEEP_FOCUS_ON_CLICK` 를 `false` 로 두면 이 트레이드오프를 반대로 바꿀 수 있다.
