# 설정 창에 가로 스크롤바가 생겼다 — 버튼 4px 키운 게 원인인 줄 알았다

- 날짜: 2026-08-09 (Phase D2.8)
- 환경: Windows 11, WebView2, CSS Grid + Flexbox

## 문제 상황

D2.8 에서 아이콘 버튼을 공통 컴포넌트로 바꾸면서 24×24 → 28×28 이 됐다. 그러자
설정 창 아래쪽에 **가로 스크롤바**가 생기고 행동 목록의 문구 입력칸이 창 밖으로 잘렸다.

산술적으로는 말이 안 됐다. 한 줄에 늘어난 건 아이콘 버튼 3개(+12px)와 카드 안쪽 여백(+4px)
정도인데, 이름칸(`.behavior__label`)은 `flex: 1 1 120px` 이라 **줄어들 여지가 충분**했다.
그런데도 이름칸은 153px 를 유지한 채 줄 전체가 넘쳤다.

## 시도한 것들

**① 계산으로 범인 찾기 → 실패.** 행 안의 요소 폭을 손으로 더해 보니 컨테이너에 들어가야
했다. 추정으로는 결론이 안 났다.

**② 기준선 캡처로 "내가 만든 회귀"인지부터 확정.** `git stash` 로 D2.8 변경을 통째로
내리고 같은 조건에서 설정 창을 캡처했다. 변경 전에는 스크롤바가 없었다 —
D2.8 이 만든 회귀임이 확정됐고, 동시에 **변경 전에도 여유가 0에 가까웠다**는 것도 보였다
(행 오른쪽 끝이 할당 폭에 딱 붙어 있었다).

**③ 눈금자를 심었다.** 추측을 끊으려고 설정 창에 임시 프로브를 넣어
`log_debug` 로 실제 폭을 stdout 에 찍었다 (`--debug-cmd` 로 창을 띄우고 밖에서 읽는다).

```
PROBE shellClient=545 shellScroll=564  li=540 row=514  kids[... label=153 ...]
```

`li=540` — 리스트 항목이 **할당 폭(497)보다 43px 크다.** 이름칸이 안 줄어든 게 아니라,
**줄이 들어갈 상자 자체가 부풀어 있었다.**

## 원인

`.behavior` 가 `display: grid` 인데 **트랙을 명시하지 않았다.** 암묵 트랙의 기본값은
`grid-auto-columns: auto` 이고, `auto` 트랙의 최대치는 **max-content** 다.

max-content 는 안쪽 요소들이 "이상적으로 원하는 폭"의 합이다. 여기서는 `<input>` 들이
각각 기본 폭(대략 20자)을 요구한다. 그 합이 컨테이너보다 커지면 **auto 트랙은 그냥 그
크기로 남고 컨테이너를 넘친다.** 블록 레이아웃이나 플렉스와 달리 줄어들지 않는다.

트랙이 514px 로 확정된 뒤에야 그 안에서 플렉스 배치가 일어나므로, 이름칸은
"자리가 남는다"고 판단해 153px 를 유지한다. **flex-shrink 는 애초에 발동할 이유가 없었다.**

원래도 max-content 가 컨테이너를 살짝 넘고 있었는데(변경 전 여유 ≈ 0), D2.8 이 28px 를
더 얹으면서 눈에 보이게 됐다. **버튼 크기는 방아쇠였고 원인이 아니었다.**

## 최종 해결법

트랙의 **최소**를 0으로 열어 준다.

```css
.behavior {
  display: grid;
  grid-template-columns: minmax(0, 1fr); /* auto = max-content 라 안 줄어든다 */
  gap: var(--sp-2);
  min-width: 0;
}
```

`minmax(0, 1fr)` 이면 트랙이 컨테이너 폭에 맞춰지고, 그제야 안쪽 플렉스가 정상 동작해
남는 자리를 이름칸이 흡수한다. 확인:

```
PROBE shellClient=545 shellScroll=545  li=497 row=471  kids[... label=110 ...]
```

`shellScroll == shellClient` — 가로 넘침 0. 덤으로 **창을 좁혀도 이제 안 깨진다**
(예전에는 max-content 아래로는 반응하지 않았다).

> `min-width: 0` 만으로는 부족했다. 그건 격자 **항목**이 줄어들 수 있게 할 뿐,
> 격자 **트랙**의 최대치가 max-content 라는 사실은 그대로다. 두 줄 다 필요하다.

## 재발 방지

- 격자 안에 폭이 유동적인 내용을 넣을 때는 `grid-template-columns` 를 **명시**한다.
  `auto` 에 맡기면 "안 줄어드는 트랙"이 조용히 생긴다
- 폭 문제는 **계산하지 말고 재라.** `--debug-cmd` + `log_debug` 로 실제 `clientWidth` /
  `scrollWidth` 를 찍는 데 5분이면 되고, 추정보다 정확하다
- UI 변경 후 회귀 여부는 **변경 전 캡처**와 비교한다. `git stash` 로 기준선을 뜨는 비용이
  "내가 만든 건가?"를 두고 헤매는 비용보다 훨씬 싸다

## 이력서 소재 한 줄

> CSS Grid 의 `auto` 트랙이 max-content 로 고정돼 컨테이너를 넘치던 레이아웃 깨짐을,
> 추정 대신 런타임 폭 계측(디버그 훅 + stdout)으로 원인을 특정하고
> `minmax(0, 1fr)` 로 해결 — 겉보기 원인(버튼 크기)과 실제 원인이 달랐던 사례.
