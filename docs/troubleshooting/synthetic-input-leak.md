# 자동 검증용 합성 입력이 사용자의 실제 작업 창으로 새어 들어갔다

- 날짜: 2026-08-05 (Phase D0)
- 관련: CLAUDE.md 「검증 정책」, `docs/decisions/0002-debug-cmd-hook.md`

## 문제 상황

GUI 앱 자동 검증을 위해 `SendInput` 으로 마우스 클릭과 키 입력을 합성했다.
목표는 "오버레이 카드가 떠도 뒤 창의 포커스를 뺏지 않는다"(B-2)를 증명하는 것.

시나리오: 메모장을 띄우고 → 클릭해 포커스를 준 뒤 → 타이핑하고
→ 카드가 뜨면 → **클릭 없이** 계속 타이핑해서 글자가 그대로 들어가는지 본다.

실제로 일어난 일:

1. `FindByTitleContains("메모장")` 이 새로 띄운 메모장이 아니라
   **이미 최소화돼 있던 사용자의 메모장**을 잡았다
2. 최소화된 창의 좌표는 `(-32000, -32000)` — 클릭이 화면 `(0,0)` 으로 갔다
3. 포커스는 그대로 사용자의 Chrome 에 있었고, 타이핑(`BEFORE-`, `AFTER`)이
   **사용자의 YouTube 탭으로** 들어갔다 (`f` = 전체화면, `t` = 극장모드 등 단축키 사정권)
4. 이후 다른 시나리오에서 테스트 창이 포그라운드를 잃어,
   화면 중앙 클릭과 `Esc` 가 **사용자의 Claude 앱으로** 들어갔다

## 시도한 것들

| 시도 | 왜 부족했나 |
| --- | --- |
| 창 제목으로 대상 찾기 | 같은 제목의 **남의 창**을 잡을 수 있다. 최소화 여부·소유 프로세스를 안 봤다 |
| 클릭 전에 대상 창 rect 확인 | 했지만 `(-32000,-32000)` 이 "최소화됨"이라는 걸 코드가 판단하지 않았다 |
| 테스트 전용 창을 새로 띄우기 | 띄웠지만 **포그라운드를 유지한다는 보장이 없다**. 사용자가 다른 창을 만지면 끝 |
| 클릭 직전 포그라운드 재확인 | 확인과 클릭 사이에 바뀔 수 있다 (TOCTOU) |

핵심: **합성 입력은 "어느 창에 도달할지"를 보장할 수 없다.**
좌표 기반 클릭은 그 순간 거기 있는 창이 먹고, 키 입력은 그 순간 포커스를 가진 창이 먹는다.
사용자의 실제 작업 세션과 검증이 같은 데스크톱을 공유하는 한 방어 코드로는 못 막는다.

## 최종 해결법

**방어가 아니라 금지.** 정책으로 차단하고 대체 경로를 만들었다.

### 1. 정책 (CLAUDE.md 「검증 정책」)

```
- 사용자 데스크톱 세션에 합성 입력(SendInput 등) 주입은 금지.
  클릭 수준 E2E가 필요하면 Windows Sandbox/VM 격리 환경에서만
```

읽기 전용 수단은 계속 허용한다 — 창 상태 검사(`EnumWindows`, `GetWindowLongW`),
화면 캡처(`CopyFromScreen`), 히트테스트(`WindowFromPoint`), 창 메시지(`PostMessage`).
**입력 주입만** 금지 대상이다.

### 2. 대체 경로 (`--debug-cmd` 훅)

클릭이 필요했던 시나리오를 **같은 핸들러 직접 호출**로 바꿨다.

```powershell
pnpm tauri dev -- -- -- --debug-cmd "wait:4000,overlay-show,wait:2000,overlay-action:done,wait:1500,dump,quit"
```

### 3. 과거 근거의 소급 무효화

이미 `SendInput` 으로 얻은 결과가 문서에 있었다. 지우지 않고 **재검증 대상으로 표시**했다.
이를 위해 검증 결과표에 **`방법` 열**을 추가했다.

| 항목 | 결과 | 방법 |
| --- | --- | --- |
| B-3 Alt+Tab 제외 | ✅ | 상태 검사 |
| B-2' 클릭 시 포커스 유지 | ⏳ 격리환경 | ~~SendInput~~ |

→ **교훈: 검증 결과에는 "무엇을 확인했나"뿐 아니라 "어떻게 확인했나"를 같이 남겨야 한다.**
방법이 나중에 무효화될 수 있고, 그때 어떤 결론을 다시 세워야 하는지 가려낼 수 있어야 한다.

## 재발 방지

- 정책을 CLAUDE.md 최상위 섹션에 배치 (세션마다 읽히는 위치)
- `--debug-cmd` 훅으로 합성 입력이 **필요할 이유 자체**를 없앰
- 새 GUI 진입점 추가 시 훅 명령도 같이 추가하는 규칙을 decisions/0002 에 명시

## 이력서 소재 한 줄

> 데스크톱 GUI 자동 검증에서 합성 입력이 사용자의 실제 작업 창으로 유입되는 사고를 겪고,
> 방어 코드 대신 "입력 주입 금지 + 앱 내 디버그 훅" 으로 구조를 바꿔 재발 가능성을 제거하고
> 검증 결과에 획득 방법을 함께 기록하는 추적 체계를 도입
